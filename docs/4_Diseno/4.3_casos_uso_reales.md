# 4.3. Casos de Uso Reales

Esta sección especifica la interacción física, tecnológica y ergonómica entre los actores y los componentes de la interfaz gráfica de usuario (GUI), referenciando de manera estricta los identificadores de controles `[1]..[65]` y las pantallas de retroalimentación `[Pantalla A]..[Pantalla N]` definidos en la Sección 4.2 (Diseño de Entrada) y Sección 4.1 (Diseño de Salida).

Cada especificación formaliza la ergonomía y dinámica operativa del sistema, garantizando la total trazabilidad entre el Catálogo de Casos de Uso ([1.5.4](file:///Users/diego/Documents/builds/owens-system/docs/1_Planificacion/1.5.4_catalogo_casos_uso.md)), las Pantallas Maestras Unificadas y las reglas de negocio del dominio gastronómico.

---

### Criterio Metodológico de Selección y Cobertura (Proceso Unificado)

En el marco metodológico del Proceso Unificado (UP / RUP), un **Caso de Uso Real** describe la concreción tecnológica de un caso de uso esencial mediante pantallas, controles físicos y eventos de entrada/salida. De los 18 Casos de Uso Extendidos analizados en la fase de análisis ([3.1.00](file:///Users/diego/Documents/builds/owens-system/docs/3_Especificacion_y_Diseno/3.1.00_especificacion_casos_uso_extendidos.md)), se desarrollan en detalle los **14 Casos de Uso Reales interactivos** que componen la totalidad de las superficies de usuario del sistema.

Aquellos casos de uso extendidos que no poseen una sección de caso de uso real interactiva independiente responden a fundamentos arquitectónicos formales:
*   **Demonios y Procesos Autónomos en Segundo Plano:** `UC-46 (Generar Solicitud de Cotización RFQ)` y `UC-48 (Fidelización por Inactividad)` son servicios desatendidos ejecutados automáticamente al detectarse quiebres de stock o ventanas de inactividad de clientes, sin intervención humana directa por pantalla.
*   **Servicios Transversales e Includes:** `UC-47 (Validar Comprobante AFIP CAE)` opera como un servicio web SOAP transaccional incluido (`<<include>>`) de forma atómica dentro de `CU-02 (Registrar Venta)` y `CU-05 (Anular Venta)`. `UC-36 (Autenticar Usuario)` opera como mecanismo perimetral de seguridad y pantalla de inicio de sesión.
*   **Tareas de Infraestructura:** `UC-42 (Ejecutar Copia de Seguridad)` se ejecuta como una tarea programada de infraestructura a nivel de servidor.

### 4.3.1. CU-15: Asignar Receta a Producto (Alta de Ficha Técnica)
[Ir al Diseño](4.2_diseno_entrada.md#421-cu-15-asignar-receta-a-producto-alta-de-ficha-tecnica)

| Metadato | Especificación |
| :--- | :--- |
| **Caso de Uso** | CU-15: Asignar Receta a Producto (articulado con CU-60: Dar de Alta Producto) |
| **Objetivos asociados** | OBJ-01, OBJ-02 (Controlar inventario mediante recetas) |
| **Requisitos asociados** | RF-15 (Ingeniería de Menú y BOM), RF-60 (Alta de Producto), RNF-01 (Integridad) |
| **Descripción** | Permite al administrador registrar un nuevo plato o combo en la carta gastronómica y parametrizar su matriz de materias primas (BOM). Al confirmarse, el plato queda habilitado en el POS mostrador y el menú digital, automatizando el descuento de stock de insumos por porción elaborada. |
| **Precondición** | - El usuario inició sesión con privilegios de Administrador.<br>- Existen insumos básicos previamente registrados en el almacén de materias primas. |

#### Secuencia normal

| Paso | Acción |
| :---: | :--- |
| **1** | El caso de uso inicia cuando el administrador selecciona la opción "Menú" [1] en la barra de navegación lateral. |
| **2** | El administrador presiona el botón de acción principal "+ Alta de Plato / Combo" [7] en la cabecera del catálogo. |
| **3** | El sistema despliega el Drawer Lateral de Ficha Técnica [3], ubicando el cursor en el campo de denominación del producto. |
| **4** | El administrador completa los datos comerciales del producto (Nombre, Descripción, Precio de Venta) en el formulario [3]. |
| **5** | El administrador selecciona la clasificación gastronómica mediante el selector "Categoría" [4] (`Hamburguesas`, `Extras`, `Combos`). |
| **6** | El administrador escoge una materia prima en el selector de insumos [5], define la cantidad consumida en el input numérico [6] y presiona el botón interactivo de añadir línea de receta. |
| **7** | El administrador repite el paso 6 hasta completar la fórmula de materias primas requeridas y presiona el botón "Guardar" [8]. |
| **8** | El sistema valida que los campos requeridos estén completos, verifica que la receta contenga al menos un insumo con cantidad mayor a cero y comprueba la unicidad del nombre. Al resultar válidas las reglas, despliega el Modal de Confirmación de Operación [Pantalla E]. |
| **9** | El administrador presiona el botón "ACEPTAR" en el Modal [Pantalla E]. |
| **10** | El sistema persiste de forma atómica el producto y sus líneas de receta en la base de datos relacional, emite la Alerta de Éxito Transaccional [Pantalla A], cierra el Drawer lateral [3] y actualiza de manera reactiva la Tabla Principal de Catálogo [9]. |

#### Postcondición
El nuevo plato y su receta quedan registrados y habilitados para comercialización en Mostrador POS y Canal Web.

#### Excepciones

| Paso | Acción |
| :---: | :--- |
| **4-7** | Si el usuario presiona "Cancelar" [10], el sistema repliega el Drawer descartando los cambios sin persistir datos. |
| **8** | Si falta completar campos obligatorios, el sistema resalta los bordes en rojo y emite la Alerta de Validación de Campos [Pantalla B]. |
| **8** | Si no se ingresaron materias primas en la receta, el sistema bloquea el avance y emite la Alerta de Inconsistencia de Receta [Pantalla C]. |
| **8** | Si el nombre del plato ya se encuentra registrado, emite la Alerta de Registro Duplicado [Pantalla D]. |
| **9** | Si el usuario presiona "CANCELAR" en [Pantalla E], el modal se cierra y el Drawer [3] permanece abierto para continuar la edición. |

#### Rendimiento y Estabilidad

| Paso | Cota de tiempo |
| :---: | :--- |
| **3** | Despliegue del Drawer lateral < 300 ms. |
| **10** | Persistencia y actualización reactiva de la grilla < 1.5 segundos. |

*   **Frecuencia:** Semanal o ante lanzamientos de carta.
*   **Estabilidad:** Alta.

### 4.3.7. CU-02: Registrar Venta en Punto de Venta (POS)
[Ir al Diseño](4.2_diseno_entrada.md#427-cu-02-registrar-venta-en-punto-de-venta-pos)

| Metadato | Especificación |
| :--- | :--- |
| **Caso de Uso** | CU-02: Registrar Venta en Punto de Venta (POS) |
| **Objetivos asociados** | OBJ-01 (Optimizar atención POS), OBJ-05 (Cumplimiento fiscal AFIP) |
| **Requisitos asociados** | RF-02 (Punto de Venta), RF-47 (Facturación AFIP), RNF-01 (Atomicidad) |
| **Descripción** | El cajero atiende un cliente en el mostrador, selecciona productos en la pantalla táctil, arma la comanda y procesa el cobro (pago único o dividido) emitiendo el ticket fiscal con autorización CAE de AFIP. |
| **Precondición** | - El usuario inició sesión con rol de Cajero.<br>- Existe una sesión de caja activa en estado "Abierta" en el puesto. |

#### Secuencia normal

| Paso | Acción |
| :---: | :--- |
| **1** | El caso de uso inicia cuando el cajero selecciona la opción "Ventas" [22] en la barra lateral. |
| **2** | El sistema inicializa una nueva comanda con orden diaria correlativa y presenta la grilla táctil y el panel de ticket vacío [25]. |
| **3** | El cajero pulsa las pestañas de categorías [23] para filtrar y presiona las tarjetas táctiles de productos [24] solicitados. |
| **4** | El sistema incorpora cada artículo al panel de ticket en vivo [25], sumando la línea y actualizando de forma reactiva el Total a cobrar [27]. |
| **5** | El cajero ajusta cantidades mediante los controles (+ / -) [26] si es necesario y presiona el botón principal "COBRAR [F12]" [28]. |
| **6** | El sistema despliega el Modal de Cobro y Facturación, exhibiendo el total adeudado. |
| **7** | El cajero selecciona el medio de pago pulsando el botón correspondiente [29] (Efectivo, Tarjeta, Transferencia, o pago mixto). |
| **8** | El cajero ingresa el dinero entregado en el input "Monto Recibido" [30]. |
| **9** | El sistema calcula instantáneamente el cambio en el display "Vuelto" [31]. |
| **10** | El cajero presiona el botón transaccional "Confirmar Pago y Facturar" [32]. |
| **11** | El sistema ejecuta una transacción atómica: solicita autorización fiscal CAE al servicio web de AFIP, descuenta del inventario las materias primas por receta, registra la venta y despliega el Modal de Facturación Exitosa con CAE [Pantalla I], disparando la impresión del ticket fiscal. |
| **12** | El cajero entrega el comprobante y el vuelto al cliente, cerrando el modal. La pantalla limpia el ticket y queda lista para el siguiente cliente. |

#### Postcondición
La venta queda cobrada y facturada con CAE, el stock de materias primas queda descontado y la orden viaja automáticamente al monitor de cocina KDS.

#### Excepciones

| Paso | Acción |
| :---: | :--- |
| **3** | Si no hay stock suficiente de materias primas para elaborar el plato, el sistema bloquea la adición y emite aviso en pantalla. |
| **8** | Si el importe digitado en el input [30] es menor al total adeudado, el botón de cobro se bloquea impidiendo la confirmación. |
| **11** | Si el Web Service de AFIP no responde tras 3 intentos, el sistema emite el comprobante en modalidad de contingencia offline con leyenda reglamentaria y encola la solicitud para reintento automático en segundo plano. |

| Paso | Acción |
| :---: | :--- |
| **1** | El cajero presiona el botón "Buscar / Anular Ticket" [33] en el encabezado del módulo de ventas. |
| **2** | El sistema despliega el cuadro de localización de comprobantes. |
| **3** | El cajero ingresa el número de ticket en el input [34] y presiona buscar. |
| **4** | El sistema recupera los datos de la venta (fecha, cajero, ítems y total) y los muestra en pantalla. |
| **5** | El cajero tipea el motivo obligatorio de la anulación en el campo de texto [35] y solicita la cancelación. |
| **6** | El sistema despliega el Modal de Confirmación de Anulación [Pantalla J], advirtiendo sobre la emisión de nota de crédito ante AFIP. |
| **7** | El cajero (o supervisor) introduce su clave de autorización y presiona "ACEPTAR". |
| **8** | El sistema cambia el estado de la venta a "Anulada", emite la Nota de Crédito fiscal electrónica, reintegra al inventario los insumos deducidos originalmente y emite la confirmación de éxito. |

#### Postcondición
La venta queda neutralizada contablemente y los insumos se reincorporan al stock disponible.
