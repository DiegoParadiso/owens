# 4.3. Casos de Uso Reales

Esta sección especifica la interacción física, tecnológica y ergonómica entre los actores y los componentes de la interfaz gráfica de usuario (GUI), referenciando de manera estricta los identificadores locales de controles `[1]..[N]` de cada Pantalla Maestra y el Catálogo Estandarizado de Pantallas de Retroalimentación `[Pantalla A]..[Pantalla F]` definidos en la Sección 4.2 (Diseño de Entrada) y Sección 4.1 (Diseño de Salida).

Cada especificación formaliza la ergonomía y dinámica operativa del sistema, garantizando la total trazabilidad entre el Catálogo de Casos de Uso ([1.5.4](file:///Users/diego/Documents/builds/owens-system/docs/1_Planificacion/1.5.4_catalogo_casos_uso.md)), las Pantallas Maestras Unificadas y las reglas de negocio del dominio gastronómico.

---

### Criterio Metodológico de Selección y Cobertura (Proceso Unificado)

En el marco metodológico del Proceso Unificado (UP / RUP), un **Caso de Uso Real** describe la concreción tecnológica de un caso de uso esencial mediante pantallas, controles físicos y eventos de entrada/salida. De los 18 Casos de Uso Extendidos analizados en la fase de análisis ([3.1.00](file:///Users/diego/Documents/builds/owens-system/docs/3_Especificacion_y_Diseno/3.1.00_especificacion_casos_uso_extendidos.md)), se desarrollan en detalle los **14 Casos de Uso Reales interactivos** que componen la totalidad de las superficies de usuario del sistema.

Aquellos casos de uso extendidos que no poseen una sección de caso de uso real interactiva independiente responden a fundamentos arquitectónicos formales:
*   **Demonios y Procesos Autónomos en Segundo Plano:** `UC-46 (Generar Solicitud de Cotización RFQ)` y `UC-48 (Fidelización por Inactividad)` son servicios desatendidos ejecutados automáticamente al detectarse quiebres de stock o ventanas de inactividad de clientes, sin intervención humana directa por pantalla.
*   **Servicios Transversales e Includes:** `UC-47 (Validar Comprobante AFIP CAE)` opera como un servicio web SOAP transaccional incluido (`<<include>>`) de forma atómica dentro de `CU-02 (Registrar Venta)` y `CU-05 (Anular Venta)`. `UC-36 (Autenticar Usuario)` opera como mecanismo perimetral de seguridad y pantalla de inicio de sesión.
*   **Tareas de Infraestructura:** `UC-42 (Ejecutar Copia de Seguridad)` se ejecuta como una tarea programada de infraestructura a nivel de servidor.

### 4.3.1. CU-15: Asignar Receta a Producto (Alta de Ficha Técnica)
[Ir al Diseño](4.2_diseno_entrada.md#421-cu-15-asignar-receta-a-producto-alta-de-ficha-tecnica)

| Metadato | Especificación |
| :--- | :--- |
| **Caso de Uso** | CU-15: Asignar Receta a Producto (articulado con CU-60: Dar de Alta Producto) |
| **Objetivos asociados** | OBJ-01, OBJ-02 (Controlar inventario mediante recetas) |
| **Requisitos asociados** | RF-15 (Ingeniería de Menú y BOM), RF-60 (Alta de Producto), RNF-01 (Integridad) |
| **Descripción** | Permite al administrador registrar un nuevo producto o combo en el menú comercial y parametrizar su matriz de materias primas (BOM). Al confirmarse, el producto queda habilitado en el POS mostrador y el menú digital, automatizando el descuento de stock de insumos por porción elaborada. |
| **Precondición** | - El usuario inició sesión con privilegios de Administrador.<br>- Existen insumos básicos previamente registrados en el almacén de materias primas. |

#### Secuencia normal

| Paso | Acción |
| :---: | :--- |
| **1** | El caso de uso inicia cuando el administrador selecciona la opción "Menú" [1] en la barra de navegación lateral. |
| **2** | El administrador presiona el botón de acción principal "+ Alta de Producto" [5] en la cabecera del catálogo. |
| **3** | El sistema despliega el Drawer Lateral de Ficha Técnica [10], ubicando el cursor en el campo "Nombre del Producto" [11]. |
| **4** | El administrador completa la denominación [11] y el importe en el input "Precio de Venta" [13]. |
| **5** | El administrador selecciona la clasificación gastronómica mediante el selector "Categoría" [12] (`Hamburguesas`, `Extras`, `Combos`). |
| **6** | El administrador escoge una materia prima en el selector de insumos componentes [14], define la cantidad consumida en el input numérico [15] y presiona el botón "+ Agregar Insumo a Receta" [16]. |
| **7** | El sistema incorpora la línea de componente a la grilla interna del Drawer y actualiza en tiempo real el display "Costo Teórico Total" [18] sumando el costo unitario ponderado. |
| **8** | El administrador repite los pasos 6 y 7 hasta completar la matriz de materias primas y presiona el botón de confirmación "Guardar" [19]. |
| **9** | El sistema valida que los campos requeridos estén completos, verifica que la receta contenga al menos un insumo con cantidad mayor a cero y comprueba la unicidad del nombre. Al resultar válidas las reglas, despliega el Modal de Confirmación de Operación [Pantalla E]. |
| **10** | El administrador presiona el botón "ACEPTAR" en el Modal [Pantalla E]. |
| **11** | El sistema persiste de forma atómica el producto y sus líneas de receta en la base de datos relacional, emite la Alerta de Éxito Transaccional [Pantalla A], cierra el Drawer lateral [10] y actualiza de manera reactiva la Tabla Principal de Catálogo [6]. |

#### Postcondición
El nuevo producto y su receta quedan registrados y habilitados para comercialización en Mostrador POS y Canal Web.

#### Excepciones

| Paso | Acción |
| :---: | :--- |
| **4** | Si el importe digitado en el input "Precio de Venta" [13] es menor o igual a cero o no numérico, el sistema resalta el campo en rojo y emite la Alerta de Validación de Campos [Pantalla B]. |
| **4-8** | Si el usuario presiona "Cancelar" [20], el sistema repliega el Drawer descartando los cambios sin persistir datos. |
| **6** | Si el usuario intenta agregar un insumo con cantidad [15] menor o igual a cero, el sistema bloquea la acción y emite la Alerta de Validación de Campos [Pantalla B]. |
| **6** | Si el insumo seleccionado en [14] ya se encuentra incorporado en la matriz BOM actual, el sistema emite la Alerta de Registro Duplicado [Pantalla D] para prevenir líneas redundantes. |
| **6-7** | Si el administrador presiona el botón "Eliminar Fila de Insumo" [17] en una línea de ingrediente agregada, el componente se remueve de la lista y se recalcula el display [18]. |
| **9** | Si falta completar campos obligatorios, el sistema resalta los bordes en rojo y emite la Alerta de Validación de Campos [Pantalla B]. |
| **9** | Si no se ingresaron materias primas en la receta (matriz BOM vacía), el sistema bloquea el avance y emite la Alerta de Inconsistencia de Receta [Pantalla C]. |
| **9** | Si el nombre del producto ya se encuentra registrado en el catálogo, emite la Alerta de Registro Duplicado [Pantalla D]. |
| **10** | Si el usuario presiona "CANCELAR" en [Pantalla E], el modal se cierra y el Drawer [10] permanece abierto con los datos cargados para continuar la edición. |
| **11** | Si ocurre un fallo de red o error de integridad transaccional en la base de datos, el sistema aborta la operación y emite la Alerta de Inconsistencia Operativa [Pantalla C]. |

#### Rendimiento y Estabilidad

| Paso | Cota de tiempo |
| :---: | :--- |
| **3** | Despliegue del Drawer lateral < 300 ms. |
| **11** | Persistencia y actualización reactiva de la grilla < 1.5 segundos. |

*   **Frecuencia:** Semanal o ante lanzamientos de nuevos productos en el menú comercial.
*   **Estabilidad:** Alta.
*   **Comentarios:** El sistema calcula el costo teórico acumulado de la receta sumando los precios unitarios ponderados de cada insumo antes de presentar la pantalla de confirmación.

### 4.3.2. CU-24: Modificar Receta (Actualización de Fórmula y Metadatos)
[Ir al Diseño](4.2_diseno_entrada.md#422-cu-24-modificar-receta-actualizacion-de-formula-y-metadatos)

| Metadato | Especificación |
| :--- | :--- |
| **Caso de Uso** | CU-24: Modificar Receta (articulado con CU-62: Modificar Producto) |
| **Objetivos asociados** | OBJ-01, OBJ-02 (Ingeniería de Menú) |
| **Requisitos asociados** | RF-24 (Modificación de Ficha Técnica), RF-62 (Actualización de Precios), RNF-01 |
| **Descripción** | Permite al administrador ajustar el precio de venta, la categoría o las proporciones de materias primas de una receta activa en el menú comercial. |
| **Precondición** | - El usuario inició sesión con rol Administrador.<br>- El producto existe registrado en el catálogo de menú. |

#### Secuencia normal

| Paso | Acción |
| :---: | :--- |
| **1** | El administrador accede a la sección "Menú" [1] en la barra de navegación lateral. |
| **2** | El administrador utiliza la barra de búsqueda [2] o las pestañas de categoría [3] para localizar el producto en la grilla [6], pudiendo navegar páginas mediante los controles de paginación [9] o restablecer filtros con el botón "Limpiar Búsqueda / Filtros" [4]. |
| **3** | El administrador presiona el Ícono de Edición (Lápiz) [7] en la fila correspondiente al producto. |
| **4** | El sistema despliega el Drawer Lateral [10] precargando el nombre [11], categoría [12], precio [13], listando los componentes BOM vigentes [14]-[15] y exhibiendo el costo acumulado [18]. |
| **5** | El administrador realiza los ajustes necesarios (modifica precio [13], incorpora nuevos insumos con [16] o elimina ingredientes obsoletos con [17]). |
| **6** | El administrador presiona el botón "Modificar" [19]. |
| **7** | El sistema valida la consistencia de los datos modificados y despliega el Modal de Confirmación de Operación [Pantalla E]. |
| **8** | El administrador presiona "ACEPTAR" en el Modal [Pantalla E]. |
| **9** | El sistema actualiza el registro en la base de datos, emite la Alerta de Éxito Transaccional [Pantalla A], repliega el Drawer [10] y refresca la fila en la grilla [6]. |

#### Postcondición
La fórmula y el precio de venta quedan actualizados para todos los pedidos futuros.

#### Excepciones

| Paso | Acción |
| :---: | :--- |
| **2** | Si el administrador desea restablecer la búsqueda y categorías de la tabla, presiona el botón "Limpiar Búsqueda / Filtros" [4], recuperando el listado completo sin recargar la página. |
| **5** | Si el usuario presiona "Cancelar" [20], el Drawer se repliega sin aplicar modificaciones. |
| **5** | Si el administrador elimina todas las materias primas dejando la fórmula vacía, el sistema bloquea el guardado y emite la Alerta de Inconsistencia de Receta [Pantalla C]. |
| **6** | Si el precio de venta [13] o las cantidades unitarias [15] son menores o iguales a cero, el sistema emite la Alerta de Validación de Campos [Pantalla B]. |
| **7** | Si la denominación modificada [11] colisiona con otro producto existente en el menú, el sistema emite la Alerta de Registro Duplicado [Pantalla D]. |
| **8** | Si el usuario presiona "CANCELAR" en [Pantalla E], regresa al Drawer [10] con los datos cargados para continuar la edición. |
| **9** | Si el producto fue modificado concurrentemente por otro usuario o falla la conexión, emite la Alerta de Inconsistencia Operativa [Pantalla C]. |

#### Rendimiento y Estabilidad

| Paso | Cota de tiempo |
| :---: | :--- |
| **4** | Precarga y despliegue del Drawer lateral con fórmula preexistente < 400 ms. |
| **9** | Persistencia transaccional y actualización reactiva de la grilla < 1.5 segundos. |

*   **Frecuencia:** Mensual o ante variaciones de costos de materias primas e inflación.
*   **Estabilidad:** Alta.
*   **Comentarios:** La modificación recalcula automáticamente el costo estándar del producto y se propaga a las futuras explosiones de consumo sin alterar históricos pasados.

### 4.3.3. CU-25: Dar de Baja Receta (Inactivación de Catálogo)
[Ir al Diseño](4.2_diseno_entrada.md#423-cu-25-dar-de-baja-receta-inactivacion-de-catalogo)

| Metadato | Especificación |
| :--- | :--- |
| **Caso de Uso** | CU-25: Dar de Baja Receta (articulado con CU-61: Dar de Baja Producto) |
| **Objetivos asociados** | OBJ-01, OBJ-02 |
| **Requisitos asociados** | RF-25 (Baja de Receta), RF-61 (Inactivación de Catálogo) |
| **Descripción** | Permite desactivar lógicamente un producto del menú comercial, retirándolo de la oferta en caja y autoservicio digital pero preservando el histórico de ventas pasadas. |
| **Precondición** | El producto se encuentra activo en el catálogo del sistema. |

#### Secuencia normal

| Paso | Acción |
| :---: | :--- |
| **1** | El administrador localiza el producto en la tabla [6] mediante la barra de búsqueda [2] o pestañas de categoría [3], pudiendo limpiar filtros con [4]. |
| **2** | El administrador presiona el Ícono de Eliminación (Papelera) [8] en la fila correspondiente. |
| **3** | El sistema verifica que el producto no forme parte de combos activos y despliega el Modal de Confirmación de Baja Lógica [Pantalla F], indicando que el producto dejará de estar disponible para su venta. |
| **4** | El administrador presiona "ACEPTAR" en el Modal [Pantalla F]. |
| **5** | El sistema marca el producto como inactivo (`is_active = false`), emite la Alerta de Éxito Transaccional [Pantalla A] y actualiza la tabla [6] reflejando su estado inhabilitado. |

#### Postcondición
El producto queda inhabilitado para futuras ventas sin comprometer la integridad de reportes contables históricos.

#### Excepciones

| Paso | Acción |
| :---: | :--- |
| **1** | Si el administrador desea restablecer los filtros para ubicar el producto en la grilla [6], presiona "Limpiar Búsqueda / Filtros" [4]. |
| **2** | Si el producto forma parte obligatoria de un Combo promocional activo vigente, el sistema bloquea la acción y emite la Alerta de Inconsistencia Operativa [Pantalla C], exigiendo desvincularlo del combo antes de darlo de baja. |
| **2** | Si existen comandas activas pendientes de cobro o elaboración con dicho producto, el sistema emite la Alerta de Inconsistencia Operativa [Pantalla C] notificando que se despacharán las órdenes en curso pero se impedirá su venta a partir de ese instante. |
| **4** | Si el administrador presiona "CANCELAR" en [Pantalla F], el modal se cierra y el producto permanece activo. |
| **5** | Si el usuario carece de permisos de administración suficientes o falla la red, el sistema emite la Alerta de Inconsistencia Operativa [Pantalla C]. |

#### Rendimiento y Estabilidad

| Paso | Cota de tiempo |
| :---: | :--- |
| **3** | Despliegue del modal de confirmación de baja < 200 ms. |
| **5** | Inactivación lógica en base de datos y actualización de grilla < 800 ms. |

*   **Frecuencia:** Ocasional (ante discontinuación de productos del menú comercial).
*   **Estabilidad:** Alta.
*   **Comentarios:** La baja lógica (`is_active = false`) previene la venta en mostrador y web preservando la integridad referencial de los reportes históricos.

| :---: | :--- |
| **1** | Si la sesión de caja se encuentra cerrada, el sistema desactiva el botón [12] y bloquea la operación emitiendo la Alerta de Inconsistencia Operativa [Pantalla C]. |
| **4** | Si el usuario presiona "Cancelar Movimiento" [17], el modal se cierra sin registrar movimientos. |
| **5** | Si faltan campos requeridos o el importe es menor o igual a cero, emite la Alerta de Validación de Fondos [Pantalla B]. |
| **6** | Si el monto de egreso supera el efectivo disponible en caja, el sistema frena la operación y emite la Alerta de Inconsistencia Operativa [Pantalla C] alertando fondos insuficientes. |
| **6** | Si el monto de extracción supera el límite operativo fijado para el cajero, el sistema exige autenticación con clave de supervisor para autorizar el egreso [Pantalla C]. |

#### Rendimiento y Estabilidad

| Paso | Cota de tiempo |
| :---: | :--- |
| **2** | Despliegue del modal de movimiento manual < 200 ms. |
| **6** | Validación, registro transaccional y recalibración de saldo esperado < 800 ms. |

*   **Frecuencia:** Baja a Media (2 a 5 registros por turno según necesidades de cambio o extracciones menores).
*   **Estabilidad:** Alta.
*   **Comentarios:** Los egresos comprueban que el saldo físico en efectivo disponible en gaveta no resulte negativo.

### 4.3.12. CU-10: Visualizar y Despachar Comandas en Cocina (KDS)

| **5** | Si el cocinero pulsa accidentalmente "ORDEN LISTA" [9], presiona el botón "Revertir Estado" [10] para regresar la orden al estado previo de cocción activa sin interrumpir la secuencia de despacho. |

#### Rendimiento y Estabilidad

| Paso | Cota de tiempo |
| :---: | :--- |
| **2** | Recepción reactiva por WebSocket y renderizado de comanda < 200 ms. |
| **4-6** | Transición de estado en base de datos y actualización de pantalla < 400 ms. |

*   **Frecuencia:** Continua durante el horario de despacho de cocina.
*   **Estabilidad:** Alta (diseñado para red local dedicada con tolerancia a microcortes).
*   **Comentarios:** El temporizador semafórico corre en el cliente para garantizar actualización fluida sin saturar peticiones al servidor.

### 4.3.14. CU-29: Generar Reporte Consolidado de Ventas y Rendición de Caja

| **Descripción** | Permite al administrador o auditor consultar el rendimiento comercial, los medios de cobro y los desvíos de caja en pantalla o descargar el documento formal estandarizado en formato PDF. |

*   **Estabilidad:** Alta.
*   **Comentarios:** El documento PDF incorpora código hash criptográfico de integridad SHA-256 para validación de inmutabilidad fiscal.
