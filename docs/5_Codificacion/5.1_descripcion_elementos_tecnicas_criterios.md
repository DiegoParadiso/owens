# 5. Codificación

## 5.1. Descripción de elementos, técnicas y criterios para la codificación

La fase de codificación materializa el diseño de software en una solución de código fuente mantenible, segura y de alto rendimiento. Para el Sistema Owens se adoptó un enfoque de **Monolito Moderno** fundamentado en la combinación de **Laravel 11, React 19 mediante Inertia.js y PostgreSQL 16**.

---

### 1. Elementos Tecnológicos del Stack

*   **Backend (Laravel 11 - PHP 8.3):** Actúa como el núcleo de lógica de negocio y persistencia. Implementa el patrón Arquitectura en Capas (Controladores, Servicios de Dominio, Modelos Eloquent y Form Requests de validación estricta).
*   **Frontend (React 19 con TypeScript):** Provee una interfaz de usuario reactiva, interactiva y tipada. La gestión del estado visual se apoya en componentes modulares sin duplicación de lógica de enrutamiento.
*   **Capa de Enlace (Inertia.js):** Conecta el backend de Laravel con los componentes de React sin requerir una API REST desacoplada compleja. Permite renderizar vistas cliente directamente desde los controladores de Laravel manteniendo la sesión y la seguridad CSRF nativas.
*   **Motor de Base de Datos (PostgreSQL 16):** Garantiza atomicidad, consistencia, aislamiento y durabilidad (ACID) en transacciones concurrentes de caja, pedidos e inventario.

---

### 2. Técnicas y Criterios de Codificación

1.  **Principios SOLID y Clean Code:**
    *   *Single Responsibility (SRP):* Controladores delgados (*Skinny Controllers*) que delegan la lógica pesada a clases de servicio (`VentaService`, `CajaService`, `RecetaService`).
    *   *Dependency Inversion (DIP):* Servicios externos (AFIP, pasarelas de pago, mensajería) se consumen a través de interfaces (`IServicioFiscal`, `IServicioMensajeria`), permitiendo tests aislados con mocks.
2.  **Validación de Entrada Blindada:**
    *   Toda petición HTTP entrante es interceptada por un `FormRequest` específico antes de alcanzar el controlador, validando tipos de datos, rangos y existencia en base de datos.
3.  **Transaccionalidad Atómica (DB Transactions):**
    *   Toda operación multi-tabla (ej. registrar una comanda, asentar su pago y descontar materias primas por receta) se encapsula dentro de `DB::transaction()`. Ante cualquier excepción, se ejecuta un rollback automático impidiendo inconsistencias de stock o fondos.
4.  **Control de Acceso Basado en Roles (RBAC):**
    *   Middlewares dedicados verifican la sesión y los permisos del usuario antes de autorizar la ejecución de cualquier método o la visualización de rutas protegidas.
