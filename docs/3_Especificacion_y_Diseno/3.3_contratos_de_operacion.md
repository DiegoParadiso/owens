# 3.3 Contratos de Operación del Sistema

---

## 3.3.1 Módulo de Ventas y Caja (POS)

---

### Contrato: `abrirSesionCaja(montoBase)`

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `abrirSesionCaja(montoBase)` |
| **Responsabilidad** | Inicializar un turno operativo de caja habilitando al cajero para registrar ventas y movimientos, estableciendo el fondo inicial de cambio en efectivo. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-01 (Abrir Sesión de Caja); RF-01 (Punto de Venta) |
| **Notas** | No puede existir más de una sesión de caja abierta simultáneamente para un mismo puesto/usuario. |
| **Excepciones** | - Si el usuario actual ya posee una sesión previa en estado "Abierta", el sistema rechaza la solicitud indicando que debe cerrarla previamente.<br>- Si `montoBase` es un valor negativo o no numérico, el sistema notifica parámetro inválido. |
| **Salida** | `unaSesion` (Instancia de `SesionCaja` inicializada con número de turno, fecha y hora). |
| **Precondición** | - El usuario se encuentra autenticado en el sistema con rol de Cajero o Administrador.<br>- El usuario no posee sesiones de caja abiertas actualmente. |
| **Postcondición** | - Se creó una instancia de SesionCaja `s`.<br>- Se asoció `s` al `Usuario` autenticado.<br>- Se asignó a `s.montoInicial` el valor de `montoBase`.<br>- Se asignó a `s.fechaHoraApertura` la fecha y hora actual del sistema.<br>- Se asignó a `s.estado` el valor "Abierta". |

---

### Contrato: `iniciarNuevaOrden()`

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `iniciarNuevaOrden()` |
| **Responsabilidad** | Crear una nueva comanda de venta en memoria vinculada a la sesión de caja activa, dejándola disponible para la incorporación progresiva de artículos. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-02 (Registrar Venta) |
| **Notas** | Operación previa al agregado recurrente de ítems de pedido. |
| **Excepciones** | Si el puesto de trabajo no cuenta con una sesión de caja abierta, el sistema impide iniciar la orden notificando que se requiere apertura de turno. |
| **Salida** | `unaComanda` (Instancia de `Comanda` con identificador temporal, estado inicial y subtotal cero). |
| **Precondición** | Existe una instancia de `SesionCaja` en estado "Abierta" para el puesto de atención actual. |
| **Postcondición** | - Se creó una instancia de Comanda `c`.<br>- Se asoció `c` a la `SesionCaja` abierta del usuario.<br>- Se asignó a `c.fechaHoraCreacion` la fecha y hora actual del sistema.<br>- Se asignó a `c.estado` el valor "En Preparación".<br>- Se asignó a `c.total` el valor 0. |

### Contrato: `agregarItem(idProducto, cantidad)`

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `agregarItem(idProducto, cantidad)` |
| **Responsabilidad** | Incorporar una línea de detalle a la comanda activa calculando el subtotal parcial en base al precio unitario vigente del producto. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-02 (Registrar Venta) |
| **Notas** | Si el producto ya figuraba en la comanda, se incrementa la cantidad consolidada. |
| **Excepciones** | - Si el `idProducto` no existe o el producto no está habilitado para la venta, el sistema emite alerta.<br>- Si el producto requiere control estricto de existencias y no hay stock disponible, el sistema notifica stock insuficiente impidiendo el agregado. |
| **Salida** | `subtotal` (Valor numérico con el importe acumulado de la comanda tras la adición). |
| **Precondición** | - Existe una instancia `c:Comanda` en estado "En Preparación".<br>- `cantidad` es un entero positivo mayor a cero.<br>- `idProducto` corresponde a un producto activo del catálogo. |
| **Postcondición** | - Se creó una instancia de LineaComanda `lc`.<br>- Se asoció `lc` a la `Comanda` `c`.<br>- Se asoció `lc` al `Producto` correspondiente al `idProducto`.<br>- Se asignó a `lc.cantidad` el valor de `cantidad`.<br>- Se asignó a `lc.precioUnitario` el precio de venta vigente del `Producto`.<br>- Se recalculó y actualizó el valor del atributo `c.total` sumando el importe de `lc`. |

### Contrato: `cerrarSesionCaja(montoFisicoEfectivo)`

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `cerrarSesionCaja(montoFisicoEfectivo)` |
| **Responsabilidad** | Consolidar los ingresos y egresos registrados durante el turno, contrastar el balance teórico del sistema contra el dinero físico declarado por el cajero y emitir el reporte final de arqueo de caja. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-03 (Cerrar Sesión de Caja); RF-01 (Punto de Venta) |
| **Notas** | Proceso irreversible que congela la actividad financiera del turno del usuario. |
| **Excepciones** | - Si el cajero ingresa un valor negativo o no numérico para `montoFisicoEfectivo`, el sistema rechaza la operación solicitando un valor válido.<br>- Si existen comandas en estado "En Preparación" sin liquidar, el sistema advierte que deben cobrarse o cancelarse antes del cierre. |
| **Salida** | `reporteArqueo` (Instancia de `ReporteArqueo` conteniendo total teórico, total físico declarado y diferencia calculada: sobrante, faltante o exacto). |
| **Precondición** | - Existe una instancia `s:SesionCaja` en estado "Abierta" asignada al usuario autenticado.<br>- El parámetro `montoFisicoEfectivo` es numérico mayor o igual a cero. |
| **Postcondición** | - Se calculó el balance teórico total de ingresos (efectivo, digital) y egresos sobre la sesión `s`.<br>- Se asignó a `s.montoCierreDeclarado` el valor de `montoFisicoEfectivo`.<br>- Se asignó a `s.diferenciaArqueo` la resta entre `montoFisicoEfectivo` y el efectivo teórico esperado.<br>- Se asignó a `s.fechaHoraCierre` la marca temporal actual del sistema.<br>- Se asignó a `s.estado` el valor "Cerrada".<br>- Se creó una instancia de ReporteArqueo `ra`.<br>- Se asoció `ra` a `s`.<br>- Se creó una instancia de RegistroAuditoria vinculando el evento de cierre a la bitácora inmutable. |

---

### Contrato: `registrarMovimientoCaja(tipoMovimiento, monto, motivo)`

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `registrarMovimientoCaja(tipoMovimiento, monto, motivo)` |
| **Responsabilidad** | Asentar un ingreso o egreso manual de dinero no vinculado a una venta ordinaria (ej. retiro para cambio, pago menor a proveedor o adelanto de sueldo) impactando en el saldo teórico del turno. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-04 (Registrar Movimiento Manual de Caja); RF-01 (Punto de Venta) |
| **Notas** | Requiere justificación textual obligatoria para fines de auditoría. |
| **Excepciones** | - Si `tipoMovimiento` es de tipo 'Retiro' y `monto` supera el efectivo disponible en caja, el sistema rechaza la operación por fondos insuficientes.<br>- Si `monto` es menor o igual a cero, o `motivo` está vacío, el sistema notifica datos inválidos. |
| **Salida** | `comprobanteMovimiento` (Recibo digital del movimiento con nuevo saldo teórico en caja). |
| **Precondición** | - Existe una `SesionCaja` en estado "Abierta" para el usuario.<br>- `tipoMovimiento` pertenece a los valores válidos: {'Ingreso', 'Retiro'}. |
| **Postcondición** | - Se creó una instancia de MovimientoCaja `mc`.<br>- Se asoció `mc` a la `SesionCaja` activa.<br>- Se asignó a `mc.tipo` el valor de `tipoMovimiento`.<br>- Se asignó a `mc.monto` el valor de `monto`.<br>- Se asignó a `mc.motivo` el texto provisto en `motivo`.<br>- Se asignó a `mc.fechaHora` la fecha y hora del sistema.<br>- Se actualizó el saldo teórico acumulado de la `SesionCaja` (sumando si es 'Ingreso', restando si es 'Retiro'). |

### Contrato: `buscarVenta(nroTicket)` (Operación de Consulta)

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `buscarVenta(nroTicket)` |
| **Responsabilidad** | Localizar en la base de datos la comanda y factura correspondientes al número de ticket especificado, verificando si se encuentra en condiciones de ser anulada o reintegrada. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-05 (Anular Venta / Registrar Devolución); RF-01 (POS) |
| **Notas** | Consulta pura previa a la anulación de una venta. |
| **Excepciones** | Si no se encuentra ninguna venta con el identificador `nroTicket`, el sistema emite un mensaje de error indicando ticket no encontrado. |
| **Salida** | `datosVenta` (Estructura con fecha, cliente, ítems, total y estado) o mensaje de error. |
| **Precondición** | El usuario tiene permisos administrativos o de supervisor sobre el módulo de ventas. |
| **Postcondición** | *(Ninguna. Operación de consulta pura; no altera el modelo conceptual)*. |

### Contrato: `anularVenta(idVenta, motivo)`

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `anularVenta(idVenta, motivo)` |
| **Responsabilidad** | Cancelar contable y fiscalmente una venta previamente cerrada, reingresando las materias primas descontadas al stock físico y emitiendo una Nota de Crédito electrónica ante AFIP. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-05 (Anular Venta / Registrar Devolución), UC-47 (Validar Comprobante Fiscal AFIP) |
| **Notas** | Operación restringida a supervisores y administradores. |
| **Excepciones** | - Si la venta ya se encontraba previamente anulada, el sistema impide una doble anulación.<br>- Si el web service de AFIP rechaza la emisión de la Nota de Crédito, la anulación se marca en estado condicional requiriendo intervención técnica. |
| **Salida** | `comprobanteAnulacion` (Instancia de Nota de Crédito con CAE y confirmación de reposición de stock). |
| **Precondición** | - Existe una `Comanda` identificada por `idVenta` en estado "Pagado".<br>- El usuario posee rol con privilegios de anulación (Supervisor/Admin). |
| **Postcondición** | - Se asignó a la `Comanda` `c` el estado "Anulado".<br>- Se creó una instancia de NotaCredito `nc`.<br>- Se asoció `nc` a `c`.<br>- Se asignó a `nc.motivo` el texto provisto en `motivo`.<br>- Se asignó a `nc.cae` el código emitido por el servicio fiscal.<br>- Se incrementó el atributo `stockActual` en cada instancia de `Insumo` según la receta de los productos despachados.<br>- Se creó una instancia de MovimientoCaja de tipo 'Retiro' compensatoria asociada a la sesión de caja del día.<br>- Se creó un RegistroAuditoria detallando la anulación y el supervisor autorizante. |

### Contrato: `confirmarReceta()`

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `confirmarReceta()` |
| **Responsabilidad** | Consolidar la fórmula de ingredientes de un producto gastronómico, persistiendo las cantidades de insumos de materias primas que componen su receta estándar. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-15 (Asignar Receta a Producto); RF-03 (Recetas e Ingeniería de Menú) |
| **Notas** | Reemplaza o versiona la receta previa del producto manteniendo trazabilidad histórica. |
| **Excepciones** | Si la lista de ingredientes temporales está vacía o algún insumo tiene cantidad menor o igual a cero, el sistema bloquea el guardado informando receta inválida. |
| **Salida** | `unaReceta` (Instancia de la nueva `Receta` con el costo de materia prima calculado consolidado). |
| **Precondición** | - Existe una instancia `prod:Producto` seleccionada en memoria.<br>- Existe una lista temporal en sesión con al menos un `Insumo` y cantidad numérica mayor a cero. |
| **Postcondición** | - Se creó una instancia de Receta `r`.<br>- Se asoció `r` al `Producto` `prod`.<br>- Por cada elemento de la lista temporal, se creó una instancia de ItemReceta `ir`.<br>- Se asoció cada `ir` a la `Receta` `r`.<br>- Se asoció cada `ir` a su respectivo `Insumo`.<br>- Se asignó a cada `ir.cantidadRequerida` la cantidad especificada en la lista temporal.<br>- Se calculó el costo total teórico de producción y se asignó al atributo `r.costoElaboracion`. |

### Contrato: `registrarLoteProduccion(idReceta, cantidadProducir)`

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `registrarLoteProduccion(idReceta, cantidadProducir)` |
| **Responsabilidad** | Asentar la elaboración de un lote de semielaborados o productos terminados a granel (ej. salsas, masas, cerveza artesanal), deduciendo los insumos base según receta e incrementando el stock del producto resultante. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-16 (Registrar Lote de Producción); RF-02 (Inventario), RF-03 (Recetas) |
| **Notas** | Cada lote recibe un identificador numérico único para control de trazabilidad bromatológica. |
| **Excepciones** | Si el stock actual de cualquiera de los insumos requeridos es insuficiente para cubrir la `cantidadProducir` estipulada, el sistema emite una alerta de quiebre de stock impidiendo iniciar la producción. |
| **Salida** | `unLote` (Instancia de `LoteProduccion` con fecha de elaboración, vencimiento estimado y rendimiento obtenido). |
| **Precondición** | - Existe una `Receta` activa identificada por `idReceta`.<br>- `cantidadProducir` es un valor numérico positivo mayor a cero.<br>- Existen existencias suficientes en almacén de todos los insumos de la receta. |
| **Postcondición** | - Se creó una instancia de LoteProduccion `lp`.<br>- Se asoció `lp` a la `Receta` correspondiente.<br>- Se asignó a `lp.cantidadProducida` el valor de `cantidadProducir`.<br>- Se asignó a `lp.fechaElaboracion` la fecha del sistema.<br>- Por cada `ItemReceta` de la receta, se descontó de `Insumo.stockActual` la cantidad proporcional (`ir.cantidadRequerida * cantidadProducir`).<br>- Se incrementó el `stockActual` del producto final o semielaborado resultante en la cantidad `cantidadProducir`. |

### Contrato: `registrarAjusteInventario(idInsumo, conteoFisico, motivo, observacion)`

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `registrarAjusteInventario(idInsumo, conteoFisico, motivo, observacion)` |
| **Responsabilidad** | Alinear el stock teórico del sistema con el recuento físico real verificado en bodega, registrando la merma, rotura o sobrante detectado junto con su justificación para auditoría. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-17 (Registrar Ajuste de Inventario); RF-02 (Inventario) |
| **Notas** | Toda modificación manual de existencias queda registrada en la bitácora inmutable de auditoría. |
| **Excepciones** | Si `conteoFisico` es un valor negativo o `idInsumo` no existe, el sistema rechaza la operación informando datos inconsistentes. |
| **Salida** | `comprobanteAjuste` (Diferencia de inventario computada y nuevo saldo de stock validado). |
| **Precondición** | - Existe una instancia `ins:Insumo` correspondiente a `idInsumo`.<br>- El usuario posee rol autorizado de Encargado de Almacén o Administrador.<br>- `motivo` pertenece al catálogo de motivos de ajuste {'Merma', 'Rotura', 'Vencimiento', 'Sobrante', 'Auditoría'}. |
| **Postcondición** | - Se creó una instancia de AjusteInventario `ai`.<br>- Se asoció `ai` al `Insumo` `ins`.<br>- Se asoció `ai` al `Usuario` que realiza el ajuste.<br>- Se asignó a `ai.stockPrevio` el valor de `ins.stockActual`.<br>- Se asignó a `ai.stockNuevo` el valor de `conteoFisico`.<br>- Se asignó a `ai.diferencia` la resta (`conteoFisico - ins.stockActual`).<br>- Se asignó a `ai.motivo` el valor de `motivo`.<br>- Se asignó a `ai.fechaHora` la fecha y hora actual del sistema.<br>- Se asignó a `ins.stockActual` el nuevo valor de `conteoFisico`.<br>- Se creó una instancia de RegistroAuditoria vinculada a la operación. |

### Contrato: `confirmarIngresoMercaderia()`

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `confirmarIngresoMercaderia()` |
| **Responsabilidad** | Dar ingreso formal y definitivo a un lote de materias primas recibidas de un proveedor, incrementando las existencias físicas en almacén y registrando la factura de compra asociada. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-21 (Registrar Ingreso de Mercadería); RF-02 (Inventario) |

| **Precondición** | - Existe una sesión de recepción en curso con proveedor identificado y número de comprobante.<br>- La lista de insumos recibidos contiene al menos un elemento con cantidad y costo unitario válidos. |
| **Postcondición** | - Se creó una instancia de RecepcionMercaderia `rm`.<br>- Se asoció `rm` al `Proveedor`.<br>- Por cada ítem de la lista temporal, se creó una instancia de DetalleRecepcion `dr`.<br>- Se asoció cada `dr` a `rm` y a su respectivo `Insumo`.<br>- Se incrementó el valor de `Insumo.stockActual` sumando la cantidad recibida en `dr`.<br>- Se actualizó el atributo `Insumo.costoUltimaCompra` con el nuevo precio pactado.<br>- Se asignó a `rm.fechaHoraIngreso` la marca temporal del sistema.<br>- Se asignó a `rm.estado` el valor "Ingresado". |

### Contrato: `despacharSolicitudCotizacion(idProveedor, listaInsumos)`

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `despacharSolicitudCotizacion(idProveedor, listaInsumos)` |
| **Responsabilidad** | Generar una solicitud formal de cotización de insumos (RFQ) y remitirla de forma automatizada por correo electrónico al proveedor seleccionado para reabastecimiento. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-46 (Módulo Inteligente de Reabastecimiento - RFQ); RF-02 (Inventario) |
| **Notas** | Registra el pliego de compras en estado "Enviada" esperando la respuesta de cotización. |
| **Excepciones** | - Si el proveedor no cuenta con dirección de correo electrónico válida configurada, el sistema aborta el despacho notificando dato faltante.<br>- Si el servidor SMTP externo falla en el envío, la solicitud se almacena en estado "Pendiente de Envío" para reintento automático. |
| **Salida** | `unaSolicitudCotizacion` (Instancia de RFQ con número de trámite, lista de insumos y constancia de envío). |
| **Precondición** | - Existe un `Proveedor` en estado "Activo" con clave `idProveedor`.<br>- `listaInsumos` contiene al menos un elemento con cantidad requerida válida. |
| **Postcondición** | - Se creó una instancia de SolicitudCotizacion `sc`.<br>- Se asoció `sc` al `Proveedor`.<br>- Por cada ítem de `listaInsumos`, se creó una instancia de ItemSolicitud `isc` asociada a `sc` y al `Insumo` correspondiente.<br>- Se asignó a `sc.fechaEmision` la fecha y hora del sistema.<br>- Se asignó a `sc.estado` el valor "Enviada".<br>- Se invocó al servicio de mensajería/correo remitiendo el documento digital al proveedor. |

## 3.3.4 Contratos de Seguridad, Fiscalidad y Módulos Inteligentes

---

### Contrato: `autenticarUsuario(identificador, contrasena)` (Operación de Consulta y Control de Acceso)

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `autenticarUsuario(identificador, contrasena)` |
| **Responsabilidad** | Validar las credenciales de acceso de un operador contrastando el hash criptográfico de la contraseña contra la base de datos y retornando el token de sesión con sus roles y permisos asignados. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-29 (Iniciar Sesión / Control de Acceso RBAC); RF-06 (Seguridad y Auditoría) |
| **Notas** | No almacena contraseñas en texto plano (usa hashing robusto con salt, e.g. bcrypt). |
| **Excepciones** | - Si las credenciales no coinciden, se incrementa el contador de intentos fallidos y se emite error de autenticación.<br>- Si el usuario supera el límite de intentos consecutivos permitidos, la cuenta se bloquea preventivamente. |
| **Salida** | `tokenSesion` (Token JWT firmado conteniendo ID de usuario, rol y vigencia) o mensaje de credenciales inválidas. |
| **Precondición** | El sistema cuenta con acceso a la base de usuarios y servicio de criptografía activo. |
| **Postcondición** | *(No altera entidades del modelo de negocio; únicamente actualiza atributos de seguridad en `Usuario`: se actualiza `ultimoAcceso` y se reinicia `intentosFallidos` a 0 si la autenticación fue exitosa)*. |

### Contrato: `ejecutarCopiaSeguridad()`

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `ejecutarCopiaSeguridad()` |
| **Responsabilidad** | Generar un volcado físico comprimido y cifrado de la base de datos institucional, registrando la operación en la bitácora inmutable de resguardo del sistema. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-41 (Gestión de Backups y Resguardo de Datos); RF-06 (Seguridad y Auditoría) |
| **Notas** | Operación restringida exclusivamente a Administradores de Sistemas. |
| **Excepciones** | Si el medio de almacenamiento de destino (local o nube) no cuenta con espacio suficiente o permisos de escritura, la operación se interrumpe y se genera alerta crítica para el administrador. |
| **Salida** | `resultadoBackup` (Instancia con nombre de archivo generado, tamaño en bytes, hash SHA-256 y marca temporal). |
| **Precondición** | El usuario autenticado posee rol de "Administrador de Sistemas". |
| **Postcondición** | - Se creó un archivo físico de backup en el medio de almacenamiento designado.<br>- Se creó una instancia de RegistroBackup `rb` en el sistema.<br>- Se asignó a `rb.nombreArchivo` la ruta y nombre del archivo generado.<br>- Se asignó a `rb.hashVerificacion` la suma de comprobación criptográfica calculada.<br>- Se asignó a `rb.fechaHora` la marca temporal del sistema.<br>- Se creó un RegistroAuditoria certificando la ejecución del backup. |

### Contrato: `solicitarEmisionComprobante(idVenta)`

| Elemento | Especificación |
| :--- | :--- |
| **Nombre Operación** | `solicitarEmisionComprobante(idVenta)` |
| **Responsabilidad** | Enviar la información fiscal de una venta al Web Service de Facturación Electrónica de la AFIP (WSFE) para obtener el Código de Autorización Electrónico (CAE) y fecha de vencimiento legal. |
| **Tipo** | Sistema |
| **Referencias Cruzadas** | UC-47 (Validar Comprobante Fiscal AFIP); RF-05 (Cumplimiento Fiscal AFIP) |
| **Notas** | Homologación fiscal obligatoria bajo normativa RG AFIP. |
| **Excepciones** | - Si el servicio de AFIP rechaza la solicitud por inconsistencia en CUIT del cliente o montos, se notifica el código de error retornado por el fisco.<br>- Si hay pérdida de conectividad, se marca la factura en estado "Pendiente de CAE" para reintento automático por worker en segundo plano. |
| **Salida** | `datosFiscales` (Estructura con CAE asignado, fecha de vencimiento de CAE, número legal de comprobante y código QR). |
| **Precondición** | - Existe una `Comanda` con clave `idVenta` en estado "Pagado".<br>- El sistema cuenta con certificado digital X.509 y clave privada válidos para autenticación ante AFIP (WSAA). |
| **Postcondición** | - Se creó una instancia de Factura `f` asociada a la comanda si no existía.<br>- Se asignó a `f.cae` el código alfanumérico otorgado por AFIP.<br>- Se asignó a `f.fechaVencimientoCae` la fecha de vigencia provista por la entidad.<br>- Se asignó a `f.numeroComprobante` el número secuencial homologado según el punto de venta fiscal.<br>- Se asignó a `f.estadoFiscal` el valor "Autorizado". |

## 3.3.5 Matriz de Trazabilidad: DSS vs. Contratos de Operación

Matriz de correspondencia entre las operaciones del Diagrama de Secuencia del Sistema (DSS) y los Contratos de Operación definidos:

| Caso de Uso | Operación del DSS | Tipo de Contrato | Impacto en Dominio |
| :--- | :--- | :--- | :--- |
| **UC-01** | `abrirSesionCaja(montoBase)` | Modificación | Crea `SesionCaja`, vincula `Usuario`. |
| **UC-02** | `iniciarNuevaOrden()` | Modificación | Crea `Comanda`, vincula a `SesionCaja`. |
| **UC-02** | `agregarItem(idProducto, cantidad)` | Modificación | Crea `LineaComanda`, actualiza total de `Comanda`. |
| **UC-02 / UC-47** | `registrarPago(metodoPago, montoRecibido)` | Modificación | Crea `Pago`, crea `Factura`, descuenta stock por receta. |
| **UC-03** | `cerrarSesionCaja(montoFisicoEfectivo)` | Modificación | Cierra `SesionCaja`, crea `ReporteArqueo` y bitácora. |
| **UC-04** | `registrarMovimientoCaja(tipoMovimiento, monto, motivo)` | Modificación | Crea `MovimientoCaja`, actualiza saldo de `SesionCaja`. |
| **UC-05** | `buscarVenta(nroTicket)` | **Consulta pura** | Localiza comanda/factura (sin cambio de estado). |
| **UC-05** | `anularVenta(idVenta, motivo)` | Modificación | Modifica estado a "Anulado", crea `NotaCredito`, repone stock. |
| **UC-10** | `consultarComandasPendientes()` | **Consulta pura** | Recupera comandas activas para KDS (sin cambio de estado). |
| **UC-10** | `iniciarPreparacion(idComanda)` | Modificación | Actualiza comanda a "En Cocción", registra hora inicio cocina. |
| **UC-10** | `marcarOrdenLista(idComanda)` | Modificación | Actualiza comanda a "Listo para Entrega", registra tiempos. |
| **UC-15** | `confirmarReceta()` | Modificación | Crea `Receta`, crea múltiples `ItemReceta` vinculados a `Insumo`. |
| **UC-16** | `registrarLoteProduccion(idReceta, cantidadProducir)` | Modificación | Crea `LoteProduccion`, descuenta insumos, aumenta producto final. |
| **UC-17** | `buscarInsumo(idInsumo)` | **Consulta pura** | Localiza insumo y existencias teóricas (sin cambio de estado). |
| **UC-17** | `registrarAjusteInventario(idInsumo, conteoFisico, motivo, observacion)` | Modificación | Crea `AjusteInventario`, actualiza `stockActual`, bitácora. |

| **UC-29** | `buscarSesionesCaja(fechaDesde, fechaHasta, idUsuario)` | **Consulta pura** | Recupera historial de sesiones y balances para reportes. |
| **UC-36** | `autenticarUsuario(identificador, contrasena)` | **Consulta / Acceso** | Valida credenciales, emite JWT (actualiza auditoría de acceso). |
| **UC-41** | `ejecutarCopiaSeguridad()` | Modificación | Crea archivo físico de backup y registro `RegistroBackup`. |
| **UC-46** | `detectarInsumosBajoPuntoPedido()` | **Consulta analítica**| Evalúa umbrales de reabastecimiento (sin cambio de estado). |
| **UC-46** | `despacharSolicitudCotizacion(idProveedor, listaInsumos)` | Modificación | Crea `SolicitudCotizacion`, crea ítems, envía email. |

| **UC-49** | `confirmarPedidoDigital(datosContacto, metodoEntrega, metodoPago)` | Modificación | Crea `PedidoDigital`, crea `Comanda`, envía a cocina KDS. |
