### 3.12 Especificación de Casos de Uso (Mitigación R08, R09 - Datos y Seguridad / Backups)

#### Caso de Uso: UC-42 Ejecutar Copia de Seguridad

**Objetivos Asociados**
*   **OBJ-07** Garantizar la seguridad, integridad y auditoría de los datos.

**Requisitos Asociados**
*   **NFR-02** Continuidad Operativa (Tolerancia a Fallos).
*   **NFR-03** Seguridad de Acceso y Datos.

**Actor Principal**
Planificador.
*(Actor Secundario: Administrador)*

**Precondición**
*   Se cumplió el horario programado para el resguardo automático (o el Administrador solicitó una copia manual tras autenticarse con `<<include>> UC-36`).
*   Existe espacio disponible en el almacenamiento local para generar el archivo.
*   El canal de comunicación con el almacenamiento externo se encuentra disponible.

**Intención del Actor**
Generar una copia de respaldo de la información del negocio (ventas, stock, recetas, usuarios y comprobantes) y guardarla en un almacenamiento externo para proteger los datos ante fallas de equipamiento.

**Propósito del Sistema**
Crear el archivo de respaldo con los datos del sistema, transferirlo al almacenamiento externo, verificar su recepción y registrar la constancia en la bitácora de auditoría.

**Descripción General**
Al cumplirse el horario programado o por solicitud del Administrador, el sistema genera un archivo de respaldo con los datos del negocio, lo envía al almacenamiento externo y asienta la operación en el registro de auditoría.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Planificador detecta el cumplimiento del horario programado para la copia de seguridad (o el Administrador solicita una copia manual). |
| 2 | El Sistema comprueba el espacio disponible localmente y la conexión con el almacenamiento externo. |
| 3 | El Sistema genera el archivo de respaldo con la información del negocio y los comprobantes digitalizados. |
| 4 | El Sistema comprime y protege el archivo de respaldo para resguardar los datos. |
| 5 | El Sistema transfiere el archivo de respaldo hacia el almacenamiento externo. |
| 6 | El Sistema comprueba la recepción correcta del archivo en el almacenamiento externo. |
| 7 | El Sistema elimina los archivos temporales generados en el equipo local. |
| 8 | El Sistema registra el resultado de la operación en la bitácora de auditoría detallando fecha, tamaño del archivo y tiempo insumido. El caso de uso finaliza. |

**Postcondición**
*   Se generó y guardó el archivo de respaldo en el almacenamiento externo.
*   Se eliminaron los archivos temporales y se registró la operación en la bitácora de auditoría.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 2 | **Espacio Insuficiente:** Si no existe espacio libre suficiente para generar el archivo, el sistema cancela la operación y notifica al Administrador. **El caso de uso finaliza.** |
| 5 | **Falla de Conexión Externa:** Si no es posible comunicarse con el almacenamiento externo, el sistema reintenta el envío. Si la falla persiste, conserva una copia local y emite un aviso al Administrador. **El caso de uso finaliza.** |
| 6 | **Archivo Incompleto o Dañado:** Si la comprobación en el almacenamiento externo detecta que el archivo recibido no coincide con el enviado, el sistema elimina la copia defectuosa y vuelve a transferir el archivo. **El caso de uso regresa al paso 5.** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 3-8 | Menor a 5 minutos, ejecutado en segundo plano sin demorar la atención en el punto de venta. |

**Frecuencia**
Diaria (automática fuera del horario de atención) y eventual (manual por el Administrador).

**Estabilidad**
Alta.

**Comentarios**
Este caso de uso mitiga el riesgo de pérdida de datos resguardando la información fuera del local comercial para permitir la recuperación ante incidentes físicos en el equipamiento.
