### 3.13 Especificación de Casos de Uso Críticos / Inteligentes (Mitigación R11 - Servicios de Terceros)

#### Caso de Uso: UC-48 Fidelización por Inactividad (Módulo Inteligente de Marketing)

**Objetivos Asociados**
*   **OBJ-08** Fidelización automatizada de clientes.

**Requisitos Asociados**
*   **NFR-02** Continuidad Operativa (Tolerancia a Fallos).
*   **NFR-05** Restricciones de Implementación (Soporte y Desacoplamiento).

**Actor Principal**
Planificador.
*(Actores Secundarios: Plataforma de Mensajería, Cliente)*

**Precondición**
*   Existe al menos una sesión de caja abierta en el local (`<<include>> UC-01`).
*   Existen reglas de inactividad y cupones configuradas en el sistema (`<<include>> UC-32`).
*   Existen clientes registrados con datos de contacto válidos.

**Intención del Actor**
Identificar a clientes que no compran hace tiempo y enviarles cupones de descuento automáticos para incentivar su regreso al local.

**Propósito del Sistema**
Revisar las fechas de compra de los clientes, detectar a quienes superen los días de inactividad configurados, generar cupones de descuento y enviar los mensajes a través de la plataforma externa sin demorar la atención en el local.

**Descripción General**
El proceso se ejecuta de forma periódica. Si el local está abierto, busca a los clientes que no registran compras desde hace más del tiempo fijado (por ejemplo, 60 días), genera cupones con fecha de vencimiento y envía las notificaciones mediante la plataforma de mensajería.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Planificador activa la rutina periódica de fidelización de clientes. |
| 2 | El Sistema verifica que el local se encuentre abierto comprobando que haya una sesión de caja activa. |
| 3 | El Sistema consulta las reglas vigentes de fidelización (días de inactividad requeridos, porcentaje de descuento y tope diario de envíos). |
| 4 | El Sistema revisa el historial de ventas e identifica a los clientes cuya última compra supere los días de inactividad y no tengan cupones vigentes. |
| 5 | El Sistema genera un cupón de descuento para cada cliente identificado, asignándole un código y una fecha de vencimiento. |
| 6 | El Sistema prepara el texto del mensaje con el nombre del cliente y el cupón asignado. |
| 7 | El Sistema envía la solicitud de despacho a la Plataforma de Mensajería externa sin demorar la atención en el local. |
| 8 | La Plataforma de Mensajería envía el mensaje al teléfono del Cliente y confirma la recepción al sistema. |
| 9 | El Sistema actualiza el registro de la campaña marcando el cupón como enviado y guarda la fecha de entrega. El caso de uso finaliza. |

**Postcondición**
*   Se generaron cupones de descuento para los clientes inactivos.
*   Se enviaron los mensajes promocionales a través de la plataforma externa.
*   Se registraron los envíos para dar seguimiento a la campaña.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 2 | **Local Cerrado:** Si no hay cajas abiertas en el local, el sistema posterga la ejecución para no enviar mensajes fuera del horario de atención. **El caso de uso finaliza.** |
| 4 | **Sin Clientes Inactivos:** Si ningún cliente cumple con los días de inactividad requeridos o ya recibieron promociones recientes, el sistema asienta que no hubo envíos en la jornada. **El caso de uso finaliza.** |
| 8 | **Falla en Plataforma Externa:** Si la plataforma de mensajería no responde o devuelve un error, el sistema reintenta el envío más tarde sin bloquear la atención en el local. Si los reintentos fallan, marca el cupón como no enviado y notifica al Administrador. **El caso de uso finaliza.** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 4-6 | Menor a 3 segundos para el análisis de clientes y generación de cupones. |
| 7-8 | Procesamiento en segundo plano sin demorar las ventas en caja. |

**Frecuencia**
Diaria (ejecución automática en horario comercial).

**Estabilidad**
Alta.

**Comentarios**
Este caso de uso automatiza el envío de promociones a clientes inactivos para fomentar su retorno al local, gestionando el envío de mensajes en segundo plano para no demorar el cobro en las cajas.
