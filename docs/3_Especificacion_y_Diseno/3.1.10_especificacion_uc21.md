# 3.1.10 Especificación de Caso de Uso UC-21: Registrar Ingreso de Mercadería

**Objetivos Asociados**
*   **OBJ-03** Digitalizar la gestión de compras.
*   **OBJ-02** Controlar el inventario mediante recetas.
*   **OBJ-07** Garantizar la seguridad, integridad y auditoría de los datos.

**Actor Principal**
Encargado de Depósito.

**Precondición**
*   El usuario inició sesión en el sistema (`<<include>> UC-36`).
*   Existe al menos un proveedor registrado en el catálogo.
*   Se dispone del remito o comprobante físico de la mercadería recibida.

**Intención del Actor**
Registrar la recepción formal de insumos entregados por un proveedor para incrementar las existencias disponibles en el inventario y asentar los costos de compra actualizados.

**Propósito del Sistema**
Incrementar el stock de las materias primas recibidas, actualizar los valores de referencia para el cálculo de costos y reposición, registrar los lotes y vencimientos bromatológicos y generar el asiento en el historial de movimientos de inventario.

**Descripción General**
El Encargado busca al proveedor, introduce los insumos detallados en el comprobante, sus cantidades, lotes, fechas de vencimiento y costos unitarios. El sistema valida los datos, incrementa las existencias en el inventario, actualiza el registro histórico de precios y genera el comprobante de recepción.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Encargado de Depósito solicita registrar un nuevo ingreso de mercadería. |
| 2 | El Sistema solicita la selección del Proveedor que efectúa la entrega. |
| 3 | El Encargado busca y selecciona al proveedor correspondiente (`<<include>> UC-54: Buscar Proveedor`). |
| 4 | El Sistema solicita la carga de los insumos detallados en el remito o factura. |
| 5 | El Encargado selecciona cada insumo (`<<include>> UC-54: Buscar Insumo`), ingresa la cantidad recibida, el número de lote, la fecha de vencimiento y el costo unitario de compra. |
| 6 | El Sistema comprueba que la fecha de vencimiento informada sea posterior a la fecha actual. |
| 7 | El Encargado repite el paso 5 hasta completar todos los artículos del comprobante y confirma la recepción. |
| 8 | El Sistema incrementa las existencias disponibles de los insumos en el inventario. |
| 9 | El Sistema actualiza el registro histórico de precios del proveedor con los nuevos valores unitarios. |
| 10 | El Sistema asienta la recepción en el historial de movimientos de inventario y confirma la registración exitosa al usuario. El caso de uso finaliza. |

**Postcondición**
*   Las existencias de insumos en el inventario quedaron incrementadas.
*   El historial de precios y costos de reposición quedó actualizado.
*   Se registró la recepción en el historial de movimientos de inventario.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 6 | **Fecha de Vencimiento Caducada:** Si la fecha informada para un lote es anterior o igual a la fecha del día, el sistema emite una advertencia de control de calidad bromatológico y bloquea el ingreso de ese lote. **El caso de uso regresa al paso 5** para verificar el comprobante o rechazar la mercadería. |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 8-10 | Menor a 2 segundos. |

**Frecuencia**
Media (1 o 2 recepciones de mercadería por jornada).

**Estabilidad**
Alta.

**Comentarios**
Este caso de uso asegura el control de calidad bromatológico y la trazabilidad de insumos alimenticios. Al asentar los costos reales de cada compra, nutre los cálculos de rentabilidad y las cotizaciones automáticas del sistema.
