# 3.1.18 Especificación de Caso de Uso UC-49: Generar Pedido Digital

**Objetivos Asociados**
*   **OBJ-01** Optimizar la atención en el Punto de Venta (POS).

**Actor Principal**
Cliente.

**Precondición**
*   El cliente accedió al portal del menú digital del establecimiento.
*   Existen productos disponibles en el catálogo de venta al público.

**Intención del Actor**
Explorar las opciones gastronómicas del menú y armar una orden de compra de forma autónoma para retiro o entrega, agilizando su atención sin requerir asistencia directa inicial en mostrador.

**Propósito del Sistema**
Exponer el catálogo de productos disponibles en tiempo real, calcular los subtotales según las personalizaciones seleccionadas, recopilar los datos del cliente y encolar la orden para su cobro y preparación.

**Descripción General**
El Cliente navega por las categorías del menú, elige los productos deseados, selecciona agregados o variantes y conforma su orden. Ingresa sus datos de entrega o retiro, selecciona la modalidad de pago y confirma. El sistema asienta el pedido y notifica al personal de mostrador.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Cliente accede a la sección de pedidos del menú digital. |
| 2 | El Sistema recupera y exhibe los productos disponibles organizados por categorías, mostrando sus nombres, descripciones y precios vigentes. |
| 3 | El Cliente selecciona un producto del menú. |
| 4 | El Sistema presenta las opciones de personalización (tamaños, ingredientes adicionales o acompañamientos). |
| 5 | El Cliente selecciona las opciones deseadas y añade el producto a su orden. |
| 6 | El Sistema actualiza el subtotal del pedido y presenta el resumen acumulado. |
| 7 | El Cliente repite los pasos 3 a 5 hasta completar su selección y solicita finalizar la orden. |
| 8 | El Sistema solicita los datos de contacto, la modalidad de entrega (retiro en local o entrega a domicilio) y la modalidad de pago. |
| 9 | El Cliente completa los datos solicitados y confirma el pedido. |
| 10 | El Sistema registra la orden en estado pendiente de cobro y preparación. |
| 11 | El Sistema notifica al personal de mostrador sobre la recepción del nuevo pedido y confirma la operación al Cliente. El caso de uso finaliza. |

**Postcondición**
*   El pedido digital quedó registrado en el sistema a la espera de su cobro y elaboración.
*   El cliente recibió la constancia con el identificador de su pedido.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 9 | **Datos de Entrega Incompletos:** Si el cliente selecciona entrega a domicilio pero omite la dirección o teléfono de contacto, el sistema informa que dichos campos son obligatorios. **El caso de uso regresa al paso 8.** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 2 | Menor a 2 segundos en el despliegue del catálogo. |

**Frecuencia**
Alta (Especialmente durante los horarios de mayor afluencia comercial).

**Estabilidad**
Alta.

**Comentarios**
Este canal de captura desatendida descongestiona la fila de espera en el mostrador del establecimiento. Al integrarse directamente con el punto de venta, garantiza que la orden ingrese al flujo de preparación de forma coordinada.
