# 3.1.16 Especificación de Caso de Uso UC-47: Validar Comprobante (Facturación AFIP)

**Objetivos Asociados**
*   **OBJ-05** Garantizar el cumplimiento fiscal (AFIP).


**Actor Principal**
Cajero (o el Sistema Automáticamente al finalizar una venta).

**Precondición**
*   La venta fue registrada exitosamente y su cobro fue confirmado (`<<include>> UC-02 Registrar Venta`).
*   El sistema cuenta con el certificado digital de AFIP vigente y configurado.

**Intención del Actor**
Obtener la autorización fiscal electrónica (CAE - Código de Autorización Electrónico) para un comprobante de venta, garantizando su validez legal ante el ente recaudador.

**Propósito del Sistema**
Compilar los datos financieros y tributarios de la venta, comunicarse de forma segura con los servidores externos de AFIP, recibir la validación fiscal y almacenar el CAE vinculándolo a la venta original para su posterior emisión y control.

**Descripción General**
Al concretarse una venta que requiere facturación fiscal, el sistema estructura los datos (importes, alícuotas, cliente) y los transmite a la AFIP. La AFIP autoriza la transacción devolviendo un CAE y su fecha de vencimiento, datos que el sistema asienta localmente para permitir la posterior emisión del ticket fiscal.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Cajero finaliza el cobro de una venta y solicita la emisión del comprobante fiscal. |
| 2 | El Sistema compila los montos netos, impuestos aplicables (IVA) y datos del receptor. |
| 3 | El Sistema aplica las firmas de seguridad requeridas al paquete de datos estructurados. |
| 4 | El Sistema establece conexión con la entidad fiscal (AFIP) y envía la petición de facturación. |
| 5 | La AFIP valida la coherencia fiscal de los importes y autoriza el comprobante. |
| 6 | La AFIP devuelve al Sistema el CAE (Código de Autorización Electrónico) y su fecha de vencimiento. |
| 7 | El Sistema asienta el CAE y el Vencimiento en el registro de la venta, marcando el comprobante como "Facturado". |
| 8 | El Sistema habilita la impresión o envío del ticket fiscal y finaliza el caso de uso. |

**Postcondición**
*   La venta quedó registrada legalmente ante AFIP con un CAE asignado.
*   El comprobante quedó disponible para su emisión con validez fiscal.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 4 | **Falla de Conexión con Entidad Fiscal:** Si el servicio externo no responde en el tiempo límite, el sistema marca el comprobante con estado "Pendiente de Facturación", programa la tarea para un reintento automático e informa al Cajero que el comprobante se facturará en diferido. **El caso de uso finaliza.** |
| 5 | **Rechazo Fiscal (Observaciones):** Si la AFIP rechaza la solicitud (ej. CUIT del cliente inválido o montos con errores), devuelve los códigos de observación. El sistema asienta el error en el registro de la venta, marca el comprobante como "Rechazado" y notifica al Cajero. **El caso de uso regresa al paso 1 (para corrección manual).** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 4-5 | La comunicación con el servicio externo debe completarse o expirar por Timeout en < 5 segundos. |

**Frecuencia**
Muy Alta (En cada venta fiscalizada).

**Estabilidad**
Alta (Depende de un tercero).

**Comentarios**
Para mitigar las caídas de AFIP durante picos de trabajo (Ej. viernes a la noche), el sistema utiliza mecanismos de reintento automático para diferir la validación sin bloquear la caja.
