### 3.1 Especificación de Casos de Uso Críticos

#### Caso de Uso: UC-03 Cerrar Sesión de Caja

**Objetivos Asociados**
*   **OBJ-01** Optimizar la atención en el Punto de Venta (POS).
*   **OBJ-07** Garantizar la seguridad, integridad y auditoría de los datos.


**Actor Principal**
Cajero.

**Precondición**
*   El usuario inició sesión en el sistema (`<<extend>> UC-36`).
*   Existe una sesión de caja abierta asignada al Cajero actual.

**Intención del Actor**
Finalizar el turno operativo y asentar los valores monetarios finales contabilizados físicamente para el arqueo.

**Propósito del Sistema**
Calcular el total teórico esperado (ingresos menos egresos), contrastarlo con el monto físico declarado por el cajero, asentar discrepancias (faltantes/sobrantes) y bloquear la operatoria de ventas.

**Descripción General**
El Cajero ingresa los montos totales físicos que contó en su gaveta. El sistema los compara contra los registros electrónicos, emite el reporte de cierre (Arqueo X/Z) y bloquea futuras transacciones hasta una nueva apertura.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Cajero solicita cerrar la sesión de caja actual. |
| 2 | El Sistema solicita al Cajero que ingrese los montos totales físicos. |
| 3 | El Cajero ingresa los montos totales contabilizados (Efectivo, Tarjeta, etc.) y confirma el cierre. |
| 4 | El Sistema valida los montos ingresados y calcula la diferencia matemática (faltante o sobrante) respecto a los ingresos electrónicos. |
| 5 | El Sistema consolida la sesión marcándola como "Cerrada", registra la fecha de cierre y bloquea las funciones de cobro. |
| 6 | El Sistema genera un reporte consolidado (Arqueo de Caja) y finaliza el caso de uso. |

**Postcondición**
*   Se registró el cierre definitivo de la sesión de caja.
*   Las funciones de cobro quedaron bloqueadas para el Cajero.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 1 | **Sin Sesión:** Si el sistema detecta que la caja ya se encontraba cerrada, notifica al usuario. **El caso de uso finaliza.** |
| 4 | **Dato Inválido:** Si el monto ingresado tiene formato incorrecto, el sistema detiene la operación, informa el error y solicita corrección. **El caso de uso regresa al paso 3.** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 6 | Generación del reporte < 2 segundos. |

**Frecuencia**
Baja (Una vez por turno por Cajero).

**Estabilidad**
Alta.

**Comentarios**
El cierre no impide que otras cajas sigan operando, ya que cada sesión es independiente por terminal/cajero.
