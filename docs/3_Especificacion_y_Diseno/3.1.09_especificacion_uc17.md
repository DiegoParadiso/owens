# 3.1.9 Especificación de Caso de Uso UC-17: Ajustar Inventario Manualmente

**Objetivos Asociados**
*   **OBJ-02** Controlar el inventario mediante recetas.
*   **OBJ-07** Garantizar la seguridad, integridad y auditoría de los datos.

**Requisitos Asociados**
*   **NFR-03** Seguridad de Acceso y Datos.

**Actor Principal**
Encargado de Depósito.
*(Actor Secundario: Administrador)*

**Precondición**
*   El usuario inició sesión en el sistema (`<<include>> UC-36`).
*   El insumo objeto de ajuste se encuentra registrado en el sistema.

**Intención del Actor**
Corregir las diferencias entre la existencia física en depósito y la cantidad registrada en el sistema, documentando el motivo del desvío (desperdicios, productos vencidos, roturas o diferencias de recuento).

**Propósito del Sistema**
Ajustar la cantidad de stock según la existencia real, clasificar el motivo de la diferencia, solicitar autorización jerárquica cuando el desvío supere los límites permitidos y registrar la operación en el historial y en la bitácora de auditoría.

**Descripción General**
El Encargado busca el insumo con diferencias, ingresa el valor del conteo real, indica el motivo y añade una observación. El sistema calcula la diferencia y, si supera el límite permitido, solicita autorización del Administrador. Al confirmarse, el sistema actualiza el stock y asienta el movimiento.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Encargado de Depósito solicita asentar un ajuste de inventario. |
| 2 | El Sistema solicita la selección del insumo a ajustar. |
| 3 | El Encargado busca y selecciona el insumo (`<<include>> UC-54: Buscar Insumo`). |
| 4 | El Sistema muestra la cantidad registrada en inventario y solicita la nueva cantidad física contada, el motivo del ajuste y una observación. |
| 5 | El Encargado ingresa el conteo físico real, selecciona el motivo (por ejemplo: Vencimiento, Rotura o Ajuste por Conteo) e ingresa la observación. |
| 6 | El Sistema calcula la diferencia entre el stock registrado y el conteo informado. |
| 7 | El Sistema valida que la cantidad informada sea numérica y no negativa. |
| 8 | El Sistema actualiza el stock disponible del insumo y registra el movimiento de ajuste en el historial. |
| 9 | El Sistema registra la operación en la bitácora de auditoría detallando el insumo modificado, la cantidad previa, la nueva cantidad, el motivo y el usuario responsable. |
| 10 | El Sistema confirma el ajuste y finaliza el caso de uso. |

**Postcondición**
*   El stock del insumo quedó actualizado con la cantidad física real.
*   Se registró el movimiento en el historial de inventario y en la auditoría.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 5 | **Diferencia Supera Límite Permitido:** Si el desvío supera el límite de pérdida permitido para el Encargado, el sistema solicita la autorización presencial del Administrador (`<<extend>> UC-36`). Si no se autoriza la operación, el sistema cancela el registro. **El caso de uso finaliza.** |
| 7 | **Dato Inválido:** Si la cantidad física ingresada no es numérica o es negativa, el sistema informa el error y solicita corrección. **El caso de uso regresa al paso 4.** |
| 8 | **Cambio Simultáneo de Stock:** Si durante la confirmación se detecta que el stock cambió por otra operación en curso, el sistema actualiza la información y solicita verificar la nueva diferencia. **El caso de uso regresa al paso 4.** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 6-9 | Menor a 1 segundo. |

**Frecuencia**
Media (Periódica en recuentos semanales o eventual ante incidentes de rotura).

**Estabilidad**
Alta.

**Comentarios**
Este caso de uso permite mantener alineado el stock registrado con el depósito real y documentar las causas de las mermas sin perder el control de responsabilidades.
