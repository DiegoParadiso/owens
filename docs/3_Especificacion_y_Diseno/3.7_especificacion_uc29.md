### 3.7 Especificación de Casos de Uso (Prioridad Alta)

#### Caso de Uso: UC-29 Consultar Historial de Sesiones de Caja

**Objetivos Asociados**
*   **OBJ-01** Optimizar la atención en el Punto de Venta (POS).
*   **OBJ-07** Garantizar la seguridad, integridad y auditoría de los datos.

**Requisitos Asociados**
*   **NFR-03** Seguridad de Acceso y Datos.

**Actor Principal**
Administrador.
*(Actor Secundario: Auditor)*

**Precondición**
*   El usuario inició sesión en el sistema (`<<include>> UC-36`).
*   El usuario posee rol con privilegios de Administrador o Auditor.

**Intención del Actor**
Revisar el rendimiento financiero, la liquidación de arqueo y el desglose de transacciones de turnos y cajeros anteriores para verificar la exactitud de los balances y detectar posibles desvíos.

**Propósito del Sistema**
Presentar la información histórica de las sesiones de caja cerradas, garantizando transparencia contable mediante la exhibición de aperturas, cierres, ventas, movimientos de dinero y diferencias de arqueo.

**Descripción General**
El Administrador introduce criterios de búsqueda por fechas o personal. El sistema recupera las sesiones correspondientes. El usuario selecciona una sesión y el sistema desglosa los importes de apertura, totales cobrados, retiros justificados y el desvío matemático (sobrante o faltante) resultante del cierre ciego.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Administrador solicita consultar el historial de sesiones de caja. |
| 2 | El Sistema solicita los parámetros de filtrado (rango de fechas desde y hasta, y usuario cajero). |
| 3 | El Administrador introduce el intervalo temporal y solicita la búsqueda. |
| 4 | El Sistema recupera los registros de sesiones de caja cerradas que coinciden con los criterios provistos. |
| 5 | El Administrador selecciona una sesión específica para examinar su balance. |
| 6 | El Sistema desglosa el fondo inicial de apertura, el total de cobros por ventas, los movimientos manuales registrados, el saldo teórico esperado y el arqueo físico declarado con su correspondiente diferencia (faltante o sobrante). |
| 7 | El Administrador revisa el informe de cierre de turno. El caso de uso finaliza. |

**Postcondición**
*   La información histórica de la sesión de caja fue consultada en modo de solo lectura.
*   Se registró la consulta del Administrador en la pista de auditoría.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 4 | **Sin Sesiones en el Período:** Si no existen sesiones de caja cerradas en el rango de fechas seleccionado, el sistema informa que no se encontraron registros. **El caso de uso regresa al paso 2.** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 4-6 | Menor a 2 segundos (NFR-01, NFR-03). |

**Frecuencia**
Media (Consulta habitual diaria o semanal de control gerencial).

**Estabilidad**
Alta.

**Comentarios**
Este caso de uso complementa la estrategia de cierre ciego de caja (mitigación R03). Al impedir que los cajeros conozcan el saldo teórico esperado antes de declarar el dinero físico, este reporte expone con precisión matemática si existieron faltantes o sobrantes al finalizar cada turno.
