### 3.1 Especificación de Casos de Uso Críticos

#### Caso de Uso: UC-01 Abrir Sesión de Caja

**Objetivos Asociados**
*   **OBJ-01** Optimizar la atención en el Punto de Venta (POS).
*   **OBJ-07** Garantizar la seguridad, integridad y auditoría de los datos.

**Requisitos Asociados**
*   **NFR-03** Seguridad de Acceso y Datos.

**Actor Principal**
Cajero.

**Precondición**
*   El usuario inició sesión en el sistema (`<<extend>> UC-36`).
*   No existe una sesión de caja activa vinculada al usuario actual.

**Intención del Actor**
Habilitar la terminal de cobro ingresando el dinero base (fondo de cambio) para iniciar la operatoria del local.

**Propósito del Sistema**
Registrar la marca de tiempo de apertura, asignar la caja al cajero responsable y habilitar la operatoria de ventas.

**Descripción General**
El Cajero especifica el monto inicial disponible en la caja. El sistema verifica que los datos sean correctos, asienta el fondo de cambio e inicia el registro financiero diario para ese usuario.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Cajero solicita abrir una nueva sesión de caja. |
| 2 | El Sistema solicita al Cajero que ingrese el monto correspondiente al fondo de cambio inicial. |
| 3 | El Cajero ingresa el monto físico disponible en la gaveta y confirma la operación. |
| 4 | El Sistema valida que el monto ingresado tenga un formato numérico correcto y sea mayor o igual a cero. |
| 5 | El Sistema asienta el monto, vincula la sesión al Cajero actual y registra la fecha y hora de apertura. |
| 6 | El Sistema habilita las funciones de cobro y finaliza el caso de uso. |

**Postcondición**
*   Se registró la apertura de caja en el sistema.
*   Las funciones de cobro quedaron habilitadas para procesar transacciones.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 1 | **Sesión Duplicada:** Si el sistema detecta que el Cajero ya posee una sesión de caja abierta en curso, informa sobre el error y bloquea la nueva apertura. **El caso de uso finaliza.** |
| 4 | **Dato Inválido:** Si el monto ingresado es negativo o contiene caracteres no numéricos, el sistema informa del error y solicita corrección. **El caso de uso regresa al paso 2.** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 3 | Menor a 1 segundo. |

**Frecuencia**
Baja (Una vez por turno por Cajero).

**Estabilidad**
Alta.

**Comentarios**
Paso obligatorio bloqueante. Ningún usuario puede invocar operaciones financieras sin ejecutar este caso de uso previamente.
