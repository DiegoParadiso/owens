### 3.2 Especificación de Casos de Uso Críticos

#### Caso de Uso: UC-16 Registrar Producción Interna

**Objetivos Asociados**
*   **OBJ-03** Digitalizar la gestión de compras.
*   **OBJ-02** Controlar el inventario mediante recetas.
*   **OBJ-07** Garantizar la seguridad, integridad y auditoría de los datos.

**Actor Principal**
Encargado de Depósito / Administrador.

**Precondición**
*   El usuario inició sesión en el sistema (`<<include>> UC-36`).
*   Existen recetas previamente configuradas en el sistema.
*   Existen insumos disponibles en el inventario.

**Intención del Actor**
Declarar la elaboración anticipada de artículos intermedios (como medallones de carne o aderezos preparados) para convertirlos en productos listos para la venta o despacho.

**Propósito del Sistema**
Calcular el consumo de materia prima según la receta, descontar los insumos utilizados, sumar la cantidad elaborada al inventario disponible y dejar constancia formal del movimiento en el registro de auditoría.

**Descripción General**
El Encargado busca el artículo a elaborar y especifica la cantidad producida. El sistema verifica si hay suficiente materia prima. De ser así, resta los insumos consumidos, suma el producto terminado al inventario y genera el registro en la pista de auditoría.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Encargado de Depósito solicita registrar una nueva producción interna. |
| 2 | El Sistema solicita la selección del producto a elaborar. |
| 3 | El Encargado busca y selecciona el artículo elaborado (`<<include>> UC-53: Buscar Producto`). |
| 4 | El Sistema presenta la fórmula del producto indicando las proporciones de insumos por unidad y solicita la cantidad total elaborada y el lote correspondiente. |
| 5 | El Encargado ingresa la cantidad de unidades fabricadas por el área de cocina y confirma la operación. |
| 6 | El Sistema calcula los insumos requeridos multiplicando la cantidad informada por la receta y verifica la disponibilidad de existencias de cada ingrediente. |
| 7 | El Sistema descuenta del inventario los insumos consumidos e incrementa la existencia del producto elaborado. |
| 8 | El Sistema asienta el detalle de la operación en el historial de movimientos de inventario y en la pista de auditoría. |
| 9 | El Sistema confirma el registro exitoso de la producción al usuario. El caso de uso finaliza. |

**Postcondición**
*   El inventario quedó actualizado con los insumos descontados y el nuevo producto sumado.
*   Se registró la operación en la pista de auditoría indicando las cantidades previas y resultantes.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 6 | **Materia Prima Insuficiente:** Si el sistema detecta que la cantidad a producir requiere más insumos de los existentes en el inventario, informa al usuario detallando los ingredientes faltantes. **El caso de uso regresa al paso 5** para que el usuario rectifique la cantidad producida. |
| 7 | **Conflicto de Operación Simultánea:** Si otra operación simultánea sobre los mismos insumos genera una inconsistencia de existencias, el sistema cancela la modificación por seguridad e informa la situación al Encargado. **El caso de uso finaliza.** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 6-8 | Menor a 2 segundos. |

**Frecuencia**
Media (Generalmente 1 o 2 veces al día, previo a la apertura del local).

**Estabilidad**
Alta.

**Comentarios**
Se aplica el principio de Segregación de Funciones: el cocinero elabora físicamente el producto, pero no cuenta con permisos para modificar las existencias del sistema. Es responsabilidad del Encargado certificar y registrar esta transformación.
