### 3.11 Especificación de Casos de Uso (Mitigación R08, R09 - Datos y Seguridad / Auditoría)

#### Caso de Uso: UC-41 Consultar Pistas de Auditoría

**Objetivos Asociados**
*   **OBJ-07** Garantizar la seguridad, integridad y auditoría de los datos.

**Requisitos Asociados**
*   **NFR-03** Seguridad de Acceso y Datos.

**Actor Principal**
Auditor.
*(Actor Secundario: Administrador)*

**Precondición**
*   El usuario inició sesión en el sistema (`<<include>> UC-36`).
*   El usuario posee permisos de auditoría o administración.
*   Existen registros de actividad previos en el sistema.

**Intención del Actor**
Consultar el historial de operaciones realizadas en el sistema (como anulaciones, ajustes de stock, retiros de caja y cambios de precios) para controlar la operatoria y verificar las acciones de los usuarios.

**Propósito del Sistema**
Permitir la búsqueda y visualización de los registros de actividad mediante filtros de fecha, usuario y módulo, mostrando los datos anteriores y posteriores a cada modificación.

**Descripción General**
El Auditor ingresa los criterios de búsqueda (fechas, usuario, módulo o tipo de acción). El sistema busca las operaciones coincidentes y las muestra ordenadas cronológicamente. El Auditor puede seleccionar cualquier registro para ver el detalle de los cambios.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Auditor solicita consultar el registro de auditoría. |
| 2 | El Sistema solicita ingresar los criterios de búsqueda (rango de fechas, usuario, módulo y tipo de acción). |
| 3 | El Auditor ingresa los filtros deseados y confirma la búsqueda. |
| 4 | El Sistema valida que la fecha desde sea menor o igual a la fecha hasta. |
| 5 | El Sistema busca y obtiene los registros que coinciden con los criterios ingresados. |
| 6 | El Sistema muestra la lista de operaciones ordenadas por fecha y hora, indicando usuario, módulo, tipo de acción y resumen. |
| 7 | El Auditor selecciona un registro para ver su detalle. |
| 8 | El Sistema muestra los datos originales y los nuevos valores resultantes de la operación. |
| 9 | El Auditor revisa la información. El caso de uso finaliza. |

**Postcondición**
*   Se consultó la información de auditoría en modo de solo lectura.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 4 | **Rango de Fechas Inválido:** Si la fecha desde es posterior a la fecha hasta, el sistema informa el error y solicita corrección. **El caso de uso regresa al paso 2.** |
| 5 | **Sin Resultados:** Si no existen registros para los filtros seleccionados, el sistema informa que no hubo coincidencias. **El caso de uso regresa al paso 3.** |
| 5 | **Búsqueda Demasiado Amplia:** Si la cantidad de resultados supera el límite de visualización en pantalla, el sistema muestra la primera página y solicita acotar las fechas. **El caso de uso regresa al paso 3.** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 5-6 | Menor a 2 segundos. |

**Frecuencia**
Media (Revisiones periódicas semanales o ante consultas puntuales).

**Estabilidad**
Alta.

**Comentarios**
Permite verificar quién realizó cada cambio importante en el sistema, protegiendo la información del negocio sin permitir la alteración ni el borrado de estos registros.
