### 3.8 Especificación de Casos de Uso (Mitigación R03 - Caja y Dinero en Efectivo)

#### Caso de Uso: UC-04 Registrar Movimiento Manual de Caja

**Objetivos Asociados**
*   **OBJ-01** Optimizar la atención en el Punto de Venta (POS).
*   **OBJ-07** Garantizar la seguridad, integridad y auditoría de los datos.

**Requisitos Asociados**
*   **NFR-03** Seguridad de Acceso y Datos.

**Actor Principal**
Cajero.
*(Actor Secundario: Administrador)*

**Precondición**
*   El usuario inició sesión en el sistema (`<<extend>> UC-36`).
*   Existe una sesión de caja abierta asignada al Cajero actual (`<<include>> UC-01`).

**Intención del Actor**
Registrar un ingreso o retiro de efectivo en la caja por motivos distintos al cobro de ventas (como refuerzo de cambio o retiros de dinero).

**Propósito del Sistema**
Registrar el monto, tipo de movimiento y motivo de la operación, actualizando el saldo esperado de la caja para el control del cierre.

**Descripción General**
El Cajero indica si la operación es un ingreso o retiro, especifica el monto y el motivo. El sistema valida los datos y, si el retiro supera el límite establecido, solicita autorización del Administrador. Al confirmarse, el sistema actualiza el saldo de la sesión y genera el comprobante.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Cajero solicita registrar un movimiento en la caja. |
| 2 | El Sistema solicita seleccionar el tipo de movimiento (Ingreso o Retiro), el monto y el motivo. |
| 3 | El Cajero selecciona el tipo de movimiento, ingresa el monto y escribe el motivo. |
| 4 | El Sistema valida que el monto sea numérico, mayor a cero y que se haya completado el motivo. |
| 5 | El Sistema comprueba que, en caso de retiro, el monto no supere el efectivo disponible en la caja. |
| 6 | El Sistema registra el movimiento vinculándolo a la sesión de caja activa y al usuario responsable. |
| 7 | El Sistema actualiza el saldo esperado de la caja y genera el comprobante del movimiento. |
| 8 | El Sistema confirma la operación al Cajero y finaliza el caso de uso. |

**Postcondición**
*   Se registró el movimiento en la sesión de caja activa.
*   El saldo esperado de efectivo quedó actualizado para el arqueo de cierre.
*   Se registró la operación en la auditoría del sistema.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 4 | **Dato Inválido:** Si el monto es menor o igual a cero, no numérico, o falta el motivo, el sistema informa el error y solicita corrección. **El caso de uso regresa al paso 2.** |
| 5 | **Efectivo Insuficiente:** Si el monto a retirar supera el efectivo disponible en la caja, el sistema bloquea la operación e informa el saldo disponible. **El caso de uso regresa al paso 3.** |
| 5 | **Retiro Supera Límite Permitido:** Si el monto a retirar supera el límite permitido sin autorización, el sistema solicita la autorización presencial del Administrador (`<<extend>> UC-36`). Si no se autoriza, el sistema cancela la operación. **El caso de uso finaliza.** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 4-7 | Menor a 1 segundo. |

**Frecuencia**
Media (1 a 4 operaciones por turno).

**Estabilidad**
Alta.

**Comentarios**
Permite registrar los ingresos y retiros de dinero ajenos a las ventas para que el arqueo de cierre refleje fielmente el dinero esperado.
