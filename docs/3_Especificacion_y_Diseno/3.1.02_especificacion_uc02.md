# 3.1.2 Especificación de Caso de Uso UC-02: Registrar Venta

**Objetivos Asociados**
*   **OBJ-01** Optimizar la atención en el Punto de Venta (POS).
*   **OBJ-02** Controlar el inventario mediante recetas.
*   **OBJ-05** Garantizar el cumplimiento fiscal (AFIP).


**Actor Principal**
Cajero.
*(Actor Secundario: Entidad Fiscal AFIP)*

**Precondición**
*   El usuario inició sesión en el sistema (`<<extend>> UC-36`).
*   Existe una Sesión de Caja abierta y asignada al Cajero actual (`<<include>> UC-01`).
*   Existe disponibilidad en el inventario.

**Intención del Actor**
Registrar los productos solicitados por el cliente, asentar el cobro y entregar un comprobante de venta válido.

**Propósito del Sistema**
Calcular el total de la transacción, asentar los ingresos, descontar el stock de forma autónoma y gestionar la autorización electrónica con la AFIP.

**Descripción General**
El Cajero ingresa los ítems del pedido. El sistema calcula los montos. El Cajero registra el o los pagos; el sistema asienta la operación, descuenta insumos, solicita autorización a AFIP y genera el ticket.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Cajero solicita iniciar una nueva orden. |
| 2 | El Sistema habilita una nueva comanda y asigna un número de ticket temporal. |
| 3 | El Cajero indica el producto solicitado y especifica la cantidad deseada. |
| 4 | El Sistema verifica la disponibilidad de stock, añade el ítem a la comanda y actualiza el subtotal. |
| 5 | El Cajero repite los pasos 3 y 4 hasta completar el pedido y solicita finalizar la selección. |
| 6 | El Sistema calcula el monto total aplicando impuestos y solicita al Cajero que ingrese el o los métodos de pago. |
| 7 | El Cajero selecciona uno o múltiples métodos de pago (ej. efectivo y tarjeta), ingresa los montos parciales hasta cubrir el total y confirma el cobro. |
| 8 | El Sistema asienta el pago, descuenta los insumos del inventario y solicita la autorización fiscal (`<<include>> UC-47`). |
| 9 | El Sistema recibe la validación de AFIP, marca la orden como "Pagada" y genera el comprobante digital (Ticket). |
| 10 | El Cajero entrega el comprobante final al cliente y el caso de uso finaliza. |

**Postcondición**
*   Se registró la venta y el monto se sumó al arqueo de la Sesión de Caja actual.
*   El stock de materias primas fue descontado lógicamente en el sistema.
*   Se generó el comprobante fiscal definitivo.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 4 | **Stock Insuficiente:** Si la receta requiere un insumo sin stock, el sistema informa al Cajero y bloquea la adición del producto a la comanda. **El caso de uso regresa al paso 3.** |
| 8 | **Fallo Fiscal (Contingencia):** Si la Entidad Fiscal (AFIP) no responde o rechaza la solicitud, el sistema guarda la venta en estado "Pendiente de Facturación" y emite un ticket de control interno para no demorar al cliente. **El caso de uso finaliza.** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 4 | Menor a 1 segundo (NFR-01). |
| 8-9 | Menor a 3 segundos. |

**Frecuencia**
Alta (Cientos de transacciones por día por local).

**Estabilidad**
Alta.

**Comentarios**
El descuento de stock es transparente para el Cajero. El sistema procesa la explosión de recetas en segundo plano sin interrumpir el flujo.
