# 3.1.7 Especificación de Caso de Uso UC-15: Asignar Receta a Insumo

**Objetivos Asociados**
*   **OBJ-02** Controlar el inventario mediante recetas.

**Actor Principal**
Encargado de Depósito / Administrador.

**Precondición**
*   El usuario inició sesión en el sistema (`<<extend>> UC-36`).
*   Tanto el artículo a componer (ej. Hamburguesa completa o Medallón casero) como los ingredientes requeridos se encuentran registrados en el catálogo.

**Intención del Actor**
Definir la fórmula de elaboración de un artículo indicando los ingredientes necesarios y sus cantidades de tolerancia (mínima y máxima) para permitir preparaciones flexibles y descuentos automáticos precisos.

**Propósito del Sistema**
Registrar la composición teórica del artículo estableciendo su período de vigencia y el rango de cantidades permitidas para cada ingrediente (cantidad mínima y máxima, admitiendo un mínimo de cero si el ingrediente es opcional), validando que un artículo no figure como componente de sí mismo.

**Descripción General**
El Administrador selecciona el artículo a componer, define la fecha de inicio de vigencia de la receta y agrega los ingredientes requeridos indicando las cantidades mínimas y máximas de cada uno. El sistema valida las reglas de consistencia y registra la fórmula.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Administrador solicita asignar una receta a un artículo del catálogo. |
| 2 | El Sistema solicita la selección del artículo y las fechas de vigencia de la receta. |
| 3 | El Administrador selecciona el artículo, ingresa la fecha de vigencia y agrega los ingredientes necesarios, indicando la cantidad mínima y máxima para cada uno. |
| 4 | El Sistema verifica que los ingredientes seleccionados existan y se encuentren activos. |
| 5 | El Sistema verifica que la cantidad mínima sea menor o igual a la cantidad máxima en cada ingrediente (admitiendo cantidad mínima igual a cero si el componente es opcional). |
| 6 | El Sistema comprueba que no existan dependencias circulares (ningún artículo puede formar parte de su propia preparación). |
| 7 | El Sistema registra la fórmula de elaboración vinculándola al artículo correspondiente. |
| 8 | El Sistema confirma que la receta fue registrada con éxito y finaliza el caso de uso. |

**Postcondición**
*   El artículo cuenta con una receta activa para el cálculo de costos, elaboración física de porciones o descuento de existencias en ventas.
*   Las fórmulas anteriores permanecen archivadas en el sistema para garantizar la trazabilidad histórica de preparaciones previas.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 4 | **Ingrediente Inactivo o Dado de Baja:** Si el sistema detecta que algún ingrediente fue deshabilitado o no existe, detiene la operación e informa al usuario. **El caso de uso regresa al paso 3.** |
| 5 | **Rango de Cantidades Inválido:** Si la cantidad mínima es mayor que la cantidad máxima, o si la cantidad máxima es menor o igual a cero, el sistema informa el error al usuario. **El caso de uso regresa al paso 3.** |
| 6 | **Dependencia Circular Detectada:** Si el artículo figura como ingrediente dentro de su propia cadena de preparación, el sistema bloquea la operación e informa la inconsistencia al usuario. **El caso de uso regresa al paso 3.** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 5-7 | Menor a 1 segundo. |

**Frecuencia**
Baja (Al incorporar nuevos platos al menú, cambiar proveedores de elaboración o reformular recetas estacionales).

**Estabilidad**
Alta.

**Comentarios**
Este caso de uso permite definir recetas con tolerancias cuantitativas e ingredientes opcionales, manteniendo siempre el historial para auditoría y control de costos.
