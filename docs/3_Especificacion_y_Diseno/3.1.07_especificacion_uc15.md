# 3.1.7 Especificación de Caso de Uso UC-15: Asignar Receta a Producto

**Objetivos Asociados**
*   **OBJ-02** Controlar el inventario mediante recetas.

**Actor Principal**
Administrador.

**Precondición**
*   El usuario inició sesión en el sistema (`<<extend>> UC-36`).
*   Tanto el producto final como los insumos (ingredientes) se encuentran registrados en el catálogo.

**Intención del Actor**
Definir la composición exacta de un producto final (ej. Hamburguesa) indicando qué insumos y en qué cantidades lo conforman, para que el sistema descuente el stock automáticamente al registrarse una venta.

**Propósito del Sistema**
Registrar la composición de la receta, verificando la consistencia de los insumos y validando que no se generen inconsistencias lógicas (como que un producto sea ingrediente de sí mismo).

**Descripción General**
El Administrador selecciona un producto final y agrega uno o más insumos, definiendo la cantidad necesaria de cada uno. El sistema valida las reglas de consistencia y registra la receta.

**Secuencia Normal**
| Paso | Acción |
| :--- | :--- |
| 1 | El caso de uso inicia cuando el Administrador solicita asignar una receta a un producto del menú. |
| 2 | El Sistema solicita la selección de los ingredientes e insumos necesarios. |
| 3 | El Administrador selecciona uno o más insumos e ingresa la cantidad requerida de cada uno. |
| 4 | El Sistema verifica que los insumos y el producto seleccionados existan y se encuentren activos. |
| 5 | El Sistema verifica que no existan inconsistencias lógicas en la receta definida (como que un producto figure como ingrediente de sí mismo). |
| 6 | El Sistema vincula los insumos al producto e identifica al artículo como compuesto por receta. |
| 7 | El Sistema confirma al Administrador que la receta fue registrada con éxito y finaliza el caso de uso. |

**Postcondición**
*   El producto quedó configurado como un artículo compuesto por receta.
*   La composición de insumos quedó registrada en el sistema para el descuento automático de inventario.

**Excepciones**
| Paso | Acción |
| :--- | :--- |
| 4 | **Insumo Inactivo o Dado de Baja:** Si el sistema detecta que algún ingrediente fue deshabilitado o no existe, detiene la operación e informa al usuario. **El caso de uso regresa al paso 2.** |
| 5 | **Estructura Inválida Detectada:** Si se detecta que el producto figura directa o indirectamente como ingrediente de sí mismo, el sistema bloquea la asignación por inconsistencia lógica e informa al usuario. **El caso de uso regresa al paso 2.** |

**Rendimiento**
| Paso | Cota de tiempo |
| :--- | :--- |
| 5-6 | Menor a 1 segundo. |

**Frecuencia**
Baja (Generalmente al incorporar o modificar platos en la carta).

**Estabilidad**
Alta.

**Comentarios**
Este caso de uso es la base para el descuento automatizado de inventario por explosión de recetas, evitando mermas ocultas y desvíos de materia prima.
